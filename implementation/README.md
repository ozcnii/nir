# Реализация ВКР

Приложение и сбор находятся в [app/](app/). Настройки Django лежат в
[app/config/](app/config/), Dockerfile и профиль Chromium в [docker/](docker/),
команды разработчика в [tools/](tools/), сквозные проверки в [tests/](tests/).
Учебные документы находятся в [thesis/](../thesis/README.md).

## Первый запуск

Из каталога `implementation/` задайте в окружении `POSTGRES_PASSWORD`,
`DB_MIGRATOR_PASSWORD`, `DB_APP_PASSWORD` и `DJANGO_SECRET_KEY`. Используйте
свои значения. `DB_NAME` по умолчанию равен `catalog`.

```sh
docker compose build app
docker compose up -d --wait db
bash tools/prepare-db.sh
docker compose up -d --wait app
```

Подготовка создаёт необходимые роли и БД, применяет миграции и выдаёт права
приложению. Подготовку одной БД выполняет один оператор за раз. Перед запуском
сайта Django проверяет миграции штатной командой `migrate --check`.
При последующих запусках используйте `docker compose up -d --wait`.
После обновления с новыми миграциями сначала выполните `tools/prepare-db.sh`.

Для подключения существующего тома PostgreSQL задайте в
`COMPOSE_PROJECT_NAME` имя из его метки `com.docker.compose.project`.
Compose использует этот том с сохранёнными объявлениями.

Сайт открыт по адресу `http://127.0.0.1:8000`. Если порт занят, задайте
свободный `APP_PORT`. Для создания администратора выполните:

```sh
docker compose exec app python -m app.manage createsuperuser
```

В обычном запуске PostgreSQL доступен сервису `app` по `db:5432`. Для прогона
с Windows через SSH подготовьте БД по шагам выше в отдельном проекте Compose
со своим `COMPOSE_PROJECT_NAME`. На машине с Docker выполните:

```sh
docker compose -f compose.yaml -f compose.ssh.yaml up -d --wait db
ssh -o ExitOnForwardFailure=yes -R 127.0.0.1:55432:127.0.0.1:55432 qq
```

В SSH-сессии на Windows задайте `DB_HOST=127.0.0.1`, `DB_PORT=55432`, имя
подготовленной базы `DB_NAME`, пароль её роли `app` в `DB_APP_PASSWORD` и
`DJANGO_SECRET_KEY`. Запустите `python -m app.manage collect <URL>` из каталога
реализации на Windows.

Добавление или снятие порта пересоздаёт контейнер БД и прерывает его соединения.
После прогона закройте SSH-сессию и выполните `docker compose up -d --wait db`
с тем же именем проекта. Основной файл уберёт привязку, том с данными сохранится.

## Поиск и сравнение

Откройте `/catalog/`, выберите сделку, категорию, регион и бюджет.
Диапазоны площади, комнат и этажа находятся в панели фильтров.
Нажмите «В сравнение» в выдаче, карточке или избранном. Откройте
`/compare/`, чтобы управлять подборкой, задавать бюджет, приоритет, режим
«Выделить различия» и пару для подробного просмотра. Строки остаются на месте. В каждой сделке можно
сравнить до шести объектов. Избранное разделено на вкладки сделок, внутри
разных типов жилья доступны дополнительные вкладки. Избранное, сравнение
и его параметры хранятся в серверной гостевой сессии Django. Браузер хранит
идентификатор сессии в cookie и выбранную тему в `localStorage`.

В карточке с несколькими публикациями видны все площадки, цены и исходные ссылки.
Снимки собраны в одной галерее. Tab входит в ленту миниатюр и следующим
нажатием переводит фокус дальше. Стрелки перемещают фокус, Enter показывает
выбранное фото.
Ниже расположен график истории цен,
точка показывает площадку, точную сумму и дату фиксации. Описания идут
следом за графиком.

Цены, галереи и исходные ссылки доступны в таблице сравнения.
При заданном бюджете подсказка учитывает варианты с точной ценой в его
пределах. Цена за м² рассчитывается для продажи квартиры при известной
точной цене и площади.
JSON доступен по `/api/properties/`, администрирование — по `/admin/`.

## Обзор цен и поиск по карте

В `/market/` можно сравнить покрытие площадок и медианную цену
по сделке, категории и региону. Для расчёта используются последние точные
цены активных объявлений. Нижние границы и пропуски отражаются отдельно.
Ссылка в каталог сохраняет выбранный срез.

В каталоге и на карте можно выбрать регион, район и станцию метро.
В списке регионов и длинных списках районов и станций можно искать по
названию. Выбранные параметры автоматически обновляют выдачу и URL.
В аренде «Квартиры» и «Комнаты» выбирают разные виды
жилья. Быстрый выбор студии или числа комнат заполняет диапазон, который
можно уточнить вручную.
Варианты района и станции берутся из адресов активных публикаций для
выбранной сделки и региона. Перемещение и приближение карты обновляют
результаты автоматически. При отсутствии координат объект доступен в списке.

Порядок результатов можно изменить по цене и площади в обе стороны. Для
цены берётся минимальная последняя сумма подходящих объявлений, включая
опубликованную нижнюю границу «от». Неизвестные значения идут в конце.
Отдельный фильтр можно снять кнопкой рядом с его значением. В URL сохраняются
применённые фильтры, сортировка и область карты.

Обычная прокрутка двигает страницу. Фильтры сохраняются
при переходе между списком и картой. Границы записываются в URL
и восстанавливаются при возврате из карточки. Точки берутся из сохранённых
координат каталога, а близкие точки группируются на текущем масштабе.
Обновление области возвращает фокус на тот же результат или на заголовок
списка, если объект ушёл из области.
Объекты без координат доступны в каталоге. Карта использует
[Leaflet 1.9.4](https://leafletjs.com/download) и
[тайлы OpenStreetMap](https://operations.osmfoundation.org/policies/tiles/).
Список остаётся доступен при ошибке картографических ресурсов.

Каталог и избранное используют одну карточку. Галерея листается прямо в
выдаче, а область фото сохраняет пропорции при отсутствии изображения.
На карточке и в выдаче сохранение обновляет состояние кнопки, счётчик и
уведомление, сохраняя текущий кадр. В избранном удаление переносит фокус на
соседнюю карточку и сохраняет просмотренные кадры. Для одного объекта «Выбрать второй» над
фотографией ведёт к подходящим объектам или в каталог. От двух до шести
объектов фотографии стоят рядом, а каждая характеристика занимает отдельную
строку. В строке «Цена» показана минимальная опубликованная цена каждого
объекта с признаком «от», если она задана нижней границей.
«Подсветить различия» и «Бюджет и критерий» доступны над таблицей. На узком
экране бюджет открывается снизу. Выбор пары сохраняет размеры колонок и
положение строк. При возврате ко всем вариантам или из карточки объекта
восстанавливается горизонтальная позиция просмотра.

Общие цвета, типографика, отступы, кнопки и поля описаны в
`design-system.css`. Иконки [Lucide](https://lucide.dev/license) поставляются
вместе с приложением, с лицензией рядом с SVG.

## Сбор

Сбор одной карточки запускается отдельной командой Django. Поддержаны
проверенные маршруты Циан, [Авито](app/collection/collectors/avito.md) и Домклик,
включая партнёрские карточки Циан и Домклик и витрину Домклик 24.
Пример запуска для Циан:

```sh
docker compose run --rm app python -m app.manage collect 'https://samara.cian.ru/sale/flat/330631159/'
```

Режим выдачи принимает одно или несколько значений `--source` и ID
субъекта из справочника. Пример продажи квартир в Самарской области
с обработкой Циан и Домклик последовательно:

```sh
docker compose run --rm app python -m app.manage collect \
  --source cian --source domclick --region 68 --property-type apartment --deal sale
```

| Источник | Областные маршруты |
| --- | --- |
| Циан | Самарская область, квартиры, комнаты и дома: продажа, месячная и суточная аренда. Саратовская область: продажа квартир. Суточные комнаты собираются прямыми запросами выдачи в браузере. |
| Домклик | Самарская область, квартиры, комнаты и дома: продажа и месячная аренда. Домклик 24: суточные квартиры, комнаты и дома в Самарской области, квартиры в Саратовской области. |
| Авито | `collect URL`. Сохранённый пример пагинации относится к городу Самаре. |

Для ограниченного прогона выдачи укажите `--max-cards N`. Лимит действует
отдельно на каждый источник и считает уникальные карточки, включая отказы.
При достижении лимита команда указывает `card_limit_reached`. В прогонах
с лимитом отдельная перепроверка сохранённых объявлений вне выдачи пропускается.

Подтверждённый областной поиск продажи квартир охватывает несколько
сегментов. Отдельный обход по `--segment` требует подтверждения фактически
применённого фильтра площадки. Если хотя бы одно сочетание не поддерживается, команда возвращает
`unsupported_collection_scope` до открытия браузера.

Обход продолжает страницы и раскрывает группы по опубликованным ключам.
Для суточных комнат Циан команда берёт ID из ответа карты и открывает
карточки из основного массива предложений. Для суточных квартир и домов
сохраняется переход через интерфейс площадки. В прямой выдаче Циан пять
полных страниц подряд без новых ID завершают обход с причиной
`pagination_no_progress`. Это неполный результат, как и потеря региона,
неподтверждённый переход или нераскрытая группа. Вывод содержит
`listing_complete: false`, допроверка ранее известных карточек источника
не начинается.

При повторном полном обходе команда также открывает ранее сохранённые
активные публикации, которых нет в выдаче. Одну публикацию можно
перепроверить через `collect URL`. Подтверждённое снятие исключает
объявление из поиска, но сохраняет карточку, связь с объектом и историю
цен. Если у объекта остаётся активное объявление на другой площадке,
объект по-прежнему доступен в результатах. Более новое активное наблюдение
восстанавливает ту же запись. Отсутствие в выдаче, HTTP-ошибка и
неопределённое состояние оставляют последнее подтверждённое состояние.

Остановка в переднем плане — `Ctrl+C`. Команда выводит в терминал итог или
ошибку. Если нужен вывод после остановки, запускайте без `--rm` и читайте
его через `docker logs ИМЯ_КОНТЕЙНЕРА`. Для веб-сервиса и БД используйте
`docker compose logs -f`.
Для остановки своего стека используйте `docker compose down`. Данные
PostgreSQL остаются в томе `db`.

## Проверки кода

```sh
uv sync --locked --dev
bash tools/check-style.sh --types
uv run --no-sync python -m app.manage check --settings=app.config.settings_base
```

Правила и границы модулей описаны в [CODING.md](../CODING.md).
Сквозная проверка в отдельном проекте Compose запускается командой
`bash tests/compose.sh`.
