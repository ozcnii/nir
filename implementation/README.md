# Реализация ВКР

Приложение и сбор находятся в [app/](app/). Настройки Django лежат в
[app/config/](app/config/), Dockerfile и профиль Chromium в [docker/](docker/),
команды разработчика в [tools/](tools/), сквозные проверки в [tests/](tests/).
Учебные документы находятся в [thesis/](../thesis/README.md).

## Первый запуск

Из каталога `implementation/` задайте в окружении `POSTGRES_PASSWORD`,
`DB_MIGRATOR_PASSWORD`, `DB_APP_PASSWORD` и `DJANGO_SECRET_KEY`. Используйте
свои значения. `DB_NAME` по умолчанию равен `catalog`.

```sh
docker compose build app
docker compose up -d --wait db
bash tools/prepare-db.sh
docker compose up -d --wait app
```

Подготовка создаёт необходимые роли и БД, применяет миграции и выдаёт права
приложению. Подготовку одной БД выполняет один оператор за раз. Перед запуском
сайта Django проверяет миграции штатной командой `migrate --check`.
При последующих запусках используйте `docker compose up -d --wait`.
После обновления с новыми миграциями сначала выполните `tools/prepare-db.sh`.

Для подключения существующего тома PostgreSQL задайте в
`COMPOSE_PROJECT_NAME` имя из его метки `com.docker.compose.project`.
Compose использует этот том с сохранёнными объявлениями.

Сайт открыт по адресу `http://127.0.0.1:8000`. Если порт занят, задайте
свободный `APP_PORT`. Для создания администратора выполните:

```sh
docker compose exec app python -m app.manage createsuperuser
```

В обычном запуске PostgreSQL доступен сервису `app` по `db:5432`. Для прогона
с Windows через SSH подготовьте БД по шагам выше в отдельном проекте Compose
со своим `COMPOSE_PROJECT_NAME`. На машине с Docker выполните:

```sh
docker compose -f compose.yaml -f compose.ssh.yaml up -d --wait db
ssh -o ExitOnForwardFailure=yes -R 127.0.0.1:55432:127.0.0.1:55432 qq
```

В SSH-сессии на Windows задайте `DB_HOST=127.0.0.1`, `DB_PORT=55432`, имя
подготовленной базы `DB_NAME`, пароль её роли `app` в `DB_APP_PASSWORD` и
`DJANGO_SECRET_KEY`. Запустите `python -m app.manage collect <URL>` из каталога
реализации на Windows.

Добавление или снятие порта пересоздаёт контейнер БД и прерывает его соединения.
После прогона закройте SSH-сессию и выполните `docker compose up -d --wait db`
с тем же именем проекта. Основной файл уберёт привязку, том с данными сохранится.

## Сбор

### Задачи, которые решает агент

Основной режим — одна команда:

```sh
python -m app.manage collect <URL> \
    --captcha-broker ./broker --captcha-agent --captcha-wait 300
```

Флаг `--captcha-agent` поднимает рядом решателя
[`tools/captcha_agent.py`](tools/captcha_agent.py): он берёт задачу из
`./broker/pending/`, решает её через `pi` и кладёт ответ в `./broker/answers/`.
Сбор применяет ответ и продолжает чтение того же документа.

| Площадка | Задача | Модель | Время | Страница открылась |
| --- | --- | --- | --- | --- |
| Авито | пазл: переместить фрагмент на пустое место | `opencode-go/deepseek-v4.1-flash` | не замерено | да |
| Циан | «Разверните картинку горизонтально» | `openai-codex/gpt-6-luna` | ~80 с | да |
| Циан | «Разверните картинку горизонтально» | `opencode-go/deepseek-v4.1-flash` | ~10 мин | ответ не проверен |

Условия: `pi auth check --model "$CAPTCHA_MODEL"` отвечает `ready`;
`CAPTCHA_MODEL` задаётся обязательно (пример — [`.env.example`](.env.example)),
без неё запуск падает с `captcha_agent_model_not_set`. Доступность модели
зависит от машины: если выбранной нет, задайте другую через `CAPTCHA_MODEL`.
Для медленной модели увеличивайте `--captcha-wait`, иначе сбор закончит
ожидание раньше ответа.

Без `--captcha-agent` тот же `--captcha-broker` работает в ручном режиме:
задача публикуется и ждёт, пока ответ положит человек. Без брокера задача
завершает источник причиной `source_captcha`.

Как устроен обход, что починено и что осталось ручным — в
[`COLLECTION-RUNTIME.md`](COLLECTION-RUNTIME.md).

Сбор одной карточки запускается отдельной командой Django. Поддержаны
проверенные маршруты Циан, [Авито](app/collection/collectors/avito.md) и Домклик,
включая партнёрские карточки Циан и Домклик и витрину Домклик 24.
Пример запуска для Циан:

```sh
docker compose run --rm app python -m app.manage collect 'https://samara.cian.ru/sale/flat/330631159/'
```

Режим выдачи принимает одно или несколько значений `--source` и ID
субъекта из справочника. Пример продажи квартир в Самарской области
с обработкой Циан и Домклик последовательно:

```sh
docker compose run --rm app python -m app.manage collect \
  --source cian --source domclick --region 68 --property-type apartment --deal sale
```

| Источник | Областные маршруты |
| --- | --- |
| Циан | Самарская область, квартиры, комнаты и дома: продажа, месячная и суточная аренда. Саратовская область: продажа квартир. Суточные комнаты собираются прямыми запросами выдачи в браузере. |
| Домклик | Самарская область, квартиры, комнаты и дома: продажа и месячная аренда. Домклик 24: суточные квартиры, комнаты и дома в Самарской области, квартиры в Саратовской области. |
| Авито | `collect URL`. Сохранённый пример пагинации относится к городу Самаре. |

Подтверждённый областной поиск продажи квартир охватывает несколько
сегментов. Отдельный обход по `--segment` требует подтверждения фактически
применённого фильтра площадки. Если хотя бы одно сочетание не поддерживается, команда возвращает
`unsupported_collection_scope` до открытия браузера.

Обход продолжает страницы и раскрывает группы по опубликованным ключам.
Для суточных комнат Циан команда берёт ID из ответа карты и открывает
карточки из основного массива предложений. Для суточных квартир и домов
сохраняется переход через интерфейс площадки. В прямой выдаче Циан пять
полных страниц подряд без новых ID завершают обход с причиной
`pagination_no_progress`. Это неполный результат, как и потеря региона,
неподтверждённый переход или нераскрытая группа. Вывод содержит
`listing_complete: false`, допроверка ранее известных карточек источника
не начинается.

### Профиль браузера и темп выборки

По умолчанию запуск открывает одноразовый Chromium. Живой прогон может
использовать постоянный профиль настоящего Chrome: cookie сохраняются
между запусками, и площадка реже показывает служебную проверку. Профиль —
отдельный каталог; профиль Chrome по умолчанию для отладки не подходит.
Именованный профиль и видимое окно имеют смысл при запуске команды на
хосте, где установлен Chrome: браузер в контейнере одноразовый и без окна.

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `COLLECTION_PROFILE` | пусто | имя каталога профиля; пусто — одноразовый контекст |
| `COLLECTION_PROFILE_ROOT` | `~/.cache/nir-collection` | где лежат именованные профили |
| `COLLECTION_BROWSER_CHANNEL` | `chromium` | `chrome` — установленный Google Chrome |
| `COLLECTION_BROWSER_HEADLESS` | `1` | `0` — окно браузера видно оператору |
| `COLLECTION_PROXY` | пусто | прокси Playwright, например `socks5://127.0.0.1:1081` |
| `COLLECTION_MAX_PAGES` | не задан | страниц выдачи на источник; пусто или `0` — без лимита |
| `COLLECTION_MAX_CARDS` | не задан | уникальных карточек выдачи на источник; пусто или `0` — без лимита |
| `COLLECTION_PAGE_PAUSE` | пусто | пауза между страницами, секунды: `5-12` или `5` |
| `COLLECTION_CARD_PAUSE` | пусто | пауза перед чтением карточки: `3-8` или `3` |

Лимит ограничивает обход выдачи: его достижение завершает источник
с `stopped_by_limit` и `listing_complete: false`, ранее известные
карточки не допроверяются. Сама допроверка не обрезается лимитом
карточек, но идёт с той же паузой. Паузы по умолчанию выключены, чтобы
сохранённые проверки не ждали; живой прогон задаёт их явно.

В Docker передавайте лимит через `-e`. Пример для продажи квартир Циан
в Самарской области ограничивает чтение выдачи 120 карточками. Сохранённых
объявлений может быть меньше, если часть карточек не удалось прочитать
или обработать.

```sh
docker compose run --rm -e COLLECTION_MAX_CARDS=120 \
  app python -m app.manage collect \
  --source cian --region 68 --property-type apartment --deal sale
```

```sh
COLLECTION_PROFILE=warm COLLECTION_BROWSER_CHANNEL=chrome \
COLLECTION_BROWSER_HEADLESS=0 COLLECTION_PAGE_PAUSE=5-12 \
COLLECTION_CARD_PAUSE=3-8 \
python -m app.manage collect --source cian --region 68 \
  --property-type apartment --deal sale
```

Остановка в переднем плане — `Ctrl+C`. Команда выводит в терминал итог или
ошибку. Если нужен вывод после остановки, запускайте без `--rm` и читайте
его через `docker logs ИМЯ_КОНТЕЙНЕРА`. Для веб-сервиса и БД используйте
`docker compose logs -f`.
Для остановки своего стека используйте `docker compose down`. Данные
PostgreSQL остаются в томе `db`.

## Проверки кода

```sh
uv sync --locked --dev
bash tools/check-style.sh --types
uv run --no-sync python -m app.manage check --settings=app.config.settings_base
```

Правила и границы модулей описаны в [CODING.md](../CODING.md).
Сквозная проверка в отдельном проекте Compose запускается командой
`bash tests/compose.sh`.
