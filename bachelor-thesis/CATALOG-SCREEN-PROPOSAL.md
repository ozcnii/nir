## Фильтры

Предлагается одна сделка за раз: продажа, месячная аренда, суточная аренда. При первом открытии продажа; это предлагаемый интерфейсный выбор, не требование НИР и не изменение API-контракта. При смене сделки сбросить денежный диапазон и вернуться на первую страницу, чтобы цена продажи не стала фильтром руб./сут. Остальные совместимые фильтры сохраняются.

Категория: любая; квартиры — любой сегмент; вторичка; новостройка; комната; дом. «Любая» включает все физические виды. «Квартиры — любой сегмент» означает только property_type=квартира, без условия market_segment: проходят квартиры с resale/new_build/NULL, комнаты и дома исключены. Конкретная вторичка/новостройка дополнительно требует соответствующий market_segment у той же подходящей ads. Вид из properties.property_type_id, сегмент конкретной ads.market_segment.

Регион — из regions; без выбора все доступные регионы. Цена от/до врублях за соответствующую сделку; площадь от/до вм²; комнаты и этаж — числовые диапазоны от/до. Поле0комнат допустимо для явно известных студий;0не означает отсутствие данных. Этаж0/отрицательный не запрещать, поскольку это допустимо принятым контрактом. Неизвестные значения не проходят заданный числовой фильтр, при отсутствии фильтра не исключают объект. Для комнаты площадь означает площадь предлагаемой комнаты, а фильтр комнат — число предлагаемых комнат из нормализованного properties.rooms, не комнат всей квартиры. При выбранной категории «Комната» подпись фильтра «Предлагаемых комнат»; при общей категории пояснение рядом с «Комнаты» раскрывает различие. Для дома площадь означает площадь дома. Площадь участка явно показывается в результате дома; отдельный фильтр участка/этажности в этом варианте не добавляется.

Видимая подпись ценового фильтра: «Последняя известная опубликованная цена». Рядом пояснение: «Фильтр учитывает известную опубликованную сумму. Для цены „от“ итог может быть выше». Это пояснение показывается пользователю на странице, а не только в документации.

Пустая граница означает отсутствие этой границы; от>до/неверный формат/несуществующий справочник — ошибка около фильтра, без молчаливой подмены. Цена фильтруется по последней известной опубликованной сумме, включая пометку «от»; совпадение диапазона с нижней ценой не обещает итоговую стоимость проживания.

## Одна карточка результата на недвижимость

Поля карточки:
- одно превью по URL подходящей публикации либо заглушка;
- подпись по физическому виду: квартира — «3-комнатная квартира, 110 м², 12/20 этаж»; комната — «Комната, 9,2 м², 1/9 этаж», при нескольких предлагаемых комнатах — «2 комнаты, …»; дом — «Дом, 100 м², 1 этаж», если этажность известна. Это примеры оформления, а не новые сетевые наблюдения;
- у дома отдельная подпись «Участок: 624 м²», если land_area_m2 известна; если нет — «Площадь участка не указана». У квартиры/комнаты этот показатель не показывается;
- опубликованный адрес; при частичном адресе показывать только имеющиеся части;
- список подходящих активных публикаций: название площадки, категория при наличии, последняя известная цена с «от»/единицей сделки и датой фиксации этой цены; при её отсутствии «Цена не получена»;
- кнопка «Открыть объект»; у публикации ссылка «На площадку».

Для примера Домклик2071752356 результат — «Комната, 9,2 м², 1/9 этаж»: roomArea9.2 и roomsOffered1 определяют нормализованные area_m2/rooms. Исходные area68.8/rooms3 относятся ко всей квартире, не копируются в нормализованные характеристики предлагаемой комнаты и не дают подпись «3-комнатная комната». Неизвестное число предлагаемых комнат не подменяется числом комнат всей квартиры.

Физические характеристики показываются один раз из properties. Блоки цен/площадок — отдельные ads, не копии объекта. Полные описания/галереи/истории остаются в подробной карточке; дополнительных раскрытий, избранного/чата/карты в каталог этим вариантом не добавляется.

Для превью предлагается первая ссылка из первой подходящей публикации со списком фото; порядок публикаций — source_code/external_id. Это стабильный технический порядок, не рейтинг качества площадок. При ошибке внешнего изображения — заглушка; новые файлы/хеши не создаются.

Дата около цены — observed_at записи последнего изменения в price_history: «цена зафиксирована…», не «проверена сейчас». ads.observed_at может продвинуться при недоступной цене и не доказывает её подтверждение; новый price_checked_at ради интерфейса не добавляем. Наличие последней известной цены не выдаётся за её текущую актуальность. Каждый ценовой блок в выдаче явно подписан «Последняя известная цена»; значение содержит «от» при from и руб./мес. либо руб./сут. для аренды, руб. для продажи. Например, фильтр до3000может включать «от3000руб./сут.»: сумма известна как нижняя граница, точный итог3000не обещается. При отсутствии истории — «Цена не получена», а не0руб.

## Несколько публикаций

Сначала отбираются активные ads, удовлетворяющие одновременно сделке/сегменту/цене. Характеристики проверяются по properties, затем результат группируется по property_id. Карточка выдачи показывает только отобранные публикации. Внутренняя страница объекта покажет остальные сохранённые публикации с их собственными состояниями/сделками и историями. Нельзя взять цену одной ads, сделку другой и получить ложный результат.

Пример из ранее проверенной пары, не новое сетевое измерение: Буянова120,110м²,3комнаты,12/20; Циан333842107 и Домклик2080269220 опубликовали24999000руб. В выдаче один объект, внутри два предложения по24999000руб., не две квартиры и не сумма49998000руб. Под конкретный сегмент попадут только публикации с подтверждённым соответствующим market_segment; у Домклик явный сегмент в этой паре не установлен. Если подходит одна публикация, показываем одну; число площадок в выдаче относится к подходящим, не ко всем историческим.

Цена продажи и цены аренды не сворачиваются в одну минимальную сумму. Показывать две суммы площадок можно без выбора «главного объявления» и без придуманного общего значения цены properties.

## Кнопки и навигация

«Найти», «Сбросить», «Открыть объект», «На площадку», «JSON», «Назад/Вперёд» по страницам результата.

«Найти» применяет фильтры и возвращает на первую страницу. «Сбросить» очищает категорию/регион/числовые диапазоны, сохраняя выбранную сделку, и возвращает на первую страницу. Изменение сделки отдельно сбрасывает ценовой диапазон. Фильтры/страница передаются в адресе, поэтому результат можно открыть по ссылке/вернуться из карточки. Отсутствующие или невалидные параметры не должны ломать страницу.

Предлагается20объектов на страницу; это размер интерфейсной страницы, не лимит сбора/полноты, не новая колонка БД. Стабильный порядок properties.id по возрастанию; настройки сортировки/обещания сортировки «по свежести цены» этим вариантом не добавляются. Пагинация считается по уникальным properties, не строкам ads. При несуществующем номере страницы — понятное сообщение и возврат к первой, не маскировка ошибки под пустую базу.

JSON возвращает ту же страницу отобранных объектов/публикаций, применяет те же фильтры, порядок и пагинацию; сохраняет принятые decimal-строки/null/списки. Полная JSON-карточка объекта остаётся отдельным чтением по принятому контракту. Точные URL и подписи контролов будут утверждены с макетом.
