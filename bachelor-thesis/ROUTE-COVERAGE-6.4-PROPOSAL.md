## 2. Поддержка и разрешение маршрута

Сохраняется5.1: до старта поддержанные значения проверяются сервером; неподдержанное сочетание не игнорируется и запуск не начинается с подменённой областью. Для маршрутов различаем:

- подтверждено: источник действительно предлагает соответствующий вид/сделку/географию, у адаптера есть проверенный способ получить направление;
- явно не предусмотрено: отсутствие сочетания установлено первичной навигацией/фильтрами/явным ответом источника, а не отсутствием ссылки в сниппете;
- не проверено: данных о поддержке/разрешении маршрута нет. Временная недоступность уже проверенного маршрута — отдельное состояние доступа, не изменение его поддерживаемости. Это не равно«пусто»или«сайт не поддерживает» и не помечается подтверждённой возможностью.

Проверенное сопоставлениеregions.name с географией источника выполняется внутри существующего адаптера по опубликованному каталогу/выбору территории источника. Используются реальные названия, тип/иерархия геоединицы и опубликованные идентификаторы, не угаданныечисла/slugs. Динамические сведения одного разрешения живут в состоянии запуска/существующем журнале; новыхтаблиц mappings/settings/профилей и полей external_code/region_code в нашейБДнет. Маршруты и способы разрешения — обязанности разработчика адаптера, не URLвводадминистратора. Неразрешённая/неоднозначная география не приводит к старту по ближайшему городу.

Предложение по предзапусковой проверке: неизвестная поддержка/неразрешённая география даёт понятную ошибку формы «маршрут/область не подтверждены», а не разрешение широкого запуска под видом полной поддержки. ## 6. Конкретный состав закрывающей проверки

Для каждого существующего адаптера/семейства, доступного в выбранной области, записать: реальную область поиска, выбранные вид/сделку, опубликованныйURLи формат выдачи; реальные ключи2конкретных единиц(еслиониесть); переходнаследующуюстраницу при еёналичии; достижимый явный конец; отдельный явный пустой запрос по реально доступным фильтрам, если такой результат воспроизводимо доступен. Не конструировать фиктивные фильтры: недоступная контрольная ситуация остаётся непроверенной, либо неприменимость обосновывается источником; без доказательства не закрывается. Длягрупп — раскрытие внутреннего списка с ключами конкретныхкарточек и внутреннимnext/«ещё», завершение/граница. Для каждого партнёрского семейства отдельно — реальная выдача→опубликованная карточка, проверенное пространство ключа без коллизий, цена с установленной единицей/отдельныйunavailable и влияние автоматически заданного срока.

В ячейке фиксируется «проверено», «явно не предусмотрено» с первичным доказательством, «не проверено/недоступно», либо «неприменимо» для внутреннегоnext, если готовый список одноcтраничный. Для действительно одностраничного семейства вторую страницу не выдумывать; возможность многостраничного обхода остаётся непроверенной, а не автоматически доказанной. Для одноcтраничного списка next неприменим с первичным основанием, но требуется наблюдаемый конец; для семейства с несколькими страницами переход остаётся обязательным. Динамические перестановки результатов отражаются как ограничение полноты, не как обещание отсутствия пропусков.
