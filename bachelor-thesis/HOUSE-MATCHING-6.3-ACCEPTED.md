## 1. Предлагаемая физическая единица

Сопоставляем одну конкретную самостоятельную единицу «дом» по принятомуproperty_type_id. «Дом»,«коттедж»,«дачный дом» сами по себе не создают новые справочники/подтипы. Незавершённость строительства сама по себе не запрещает конкретный индивидуально определённый дом.

- В collection должно быть однозначно установлено, что публикация предлагает один конкретный дом/самостоятельный адресуемый жилой блок. Самостоятельный блок/секция допускается только когда в существующемaddress можно сохранить явно опубликованные обозначение области и её идентификатор(например«дом7,блок2»с соответствующей иерархией). Идентификатор не берётся из номера фото/плана. Если блок обозначен, но область/идентификатор не сохраняются однозначно, active-снимокrejected: он не записывается как обычный целый дом. Для блока общее разрешениеNULLадреса ниже не применяется. Сохранённый квалификатор входит в идентичность и не теряется при сравнении с целым зданием.
- Явный каталог проектов, типовой проект без конкретного объекта, предложение строительства на любом участке, только участок без дома не нормализуются как конкретный дом. При обязательномнеустановленномфизическомвиде/единице — rejectedсдиагностикой, не новаяproperty_type/пустаяproperties. Рекламное описание/названиеКПилиотсутствие номера дома САМИПОСЕБЕ не доказывают, что это каталог: не отбрасывать конкретную карточку без основания.
- Доля/часть без однозначно выделенной самостоятельной физической единицы не становится целым домом: rejected. При явно самостоятельном адресуемом блоке/единице сохраняются её собственные адрес/площадь; не подменять площадью всего здания. Если роль/самостоятельность неоднозначна, отказ от предположения, не юридическая экспертиза.
- Явное совместное предложение нескольких домов не разбивается на выдуманные записи и не становится одним домом с суммарной площадью. В принятой схеме нет числа/состава домов: такой active-снимокrejected. Комнатный набор из6.2на дома автоматически не распространяется.
- Для одного определённого целого дома отсутствие площади/этажности/участка/номера — достоверныеNULLполя по принятому4.2, сохранение отдельнойproperties возможно. Для самостоятельного блока требуется указанное выше сохраняемое обозначение его области/идентификатора. Отсутствие необязательного поля не означает, что дом не существует.

Классификация выполняется collectionдоcatalog. Вновь принятые активные записи типа«дом» тем самым имеют инвариант одной самостоятельной единицы; дополнительный столбец классификации не вводится. Неизвестную/противоречивую единицу не передаём как положительный дом.

Числа/единицы/NULL—принятый4.2. Площадь участка не равна площади здания. Значения реестра/отчёта/террасы/жилой части не подменяют основную объявленную общую площадь. Достоверный внутренний конфликт СОПОСТАВИМЫХ величин одной предлагаемой единицы применяетсяrejected, а неNULLи не среднее/допуск. Разные показатели разных блоков(например общаяи жилая) не объявляются конфликтом только из-за разных чисел. Это принятое владельцем уточнение4.2для домов.

Длясопоставления не вводятся ни произвольный допуск площадей, ни дистанция«близко», ни исправление по более удобной цифре. Цена/deal_type/продавец/фотоURL/совпавший рекламный текст не устанавливают физическую идентичность.

## 3. Новая публикация: точное правило

1. Предварительные кандидаты: propertiesвида«дом», тотжеregion_id, таже однозначно опубликованная иерархия населённого пункта/территории, тип и название улицы, дом/корпус. СохранятьСНТ/КП/посёлок и родительскую иерархию. Не приравнивать отображаемуюСамару к любому вложенномуСНТ. Длябезуличнойадреснойструктуры требуется совпадающая опубликованная цепочка соответствующих адресных компонентов, а не город+номер.
2. Положительная идентичность: полностью совпадает опубликованный адрес ИМЕННО здания/блока, включая адресный номер дома, корпус/строение/блок, если они выделены. Еслиномер одного компонента известен только у однойстороны и без него не определяется та же единица, положительного результата нет. Самый короткий адрес без номера не считается полным.
3. «Участок№17» не превращается в «дом17». Одного участка/координат/КП недостаточно: на участке могут быть разные здания. Еслиисточник прямо описываетнесколько зданий под одним адресом без номера конкретного строения/блока, положительной идентичности нет. Не делать вывод о множестве зданий только по числуфото/рекламномустилю.
4. Уобеихсторон известны и точно совпадают area_m2иfloors_total. Это обязательные физические опоры к конкретному адресу. Еслионинеизвестны, отдельнаяproperties, безпредположения«одноэтажный». Общиеизвестные roomsиland_area_m2такжедолжнысовпасть. Еслиэтотпризнакизвестентолькоуоднойстороны, сампосебеоннепротиворечие. Разные известные площадиучасткадаютотказотattach, невыборбольшейилисредней. floorдляцелогодомаNULL.
5. Конечныйсписоксравниваемыхполей: region_id,property_type_id,address,area_m2,floors_total,rooms,land_area_m2. latitude/longitude,floor,цена,описание,источник/ключне являются дополнительным баллом идентичности(собственный source/key отдельно идентифицирует публикацию). Спальни не подставляются.
6. Выбираем properties, прошедшие ВСЕположительныеусловия. Ровноодна→attach,нольилинесколько→отдельнаяproperties. Много предварительных домов однойулицы неошибка. ПервыйIDневыбирается; частичныйадрес/похожийтекстнеослабляюттребования.
7. Сравнениепроводитсяспризнакамиоднойкандидатнойproperties. Совместимыйpatchтолькодополняетнеизвестное; известныеплощадь/этажность/комнаты/участокнеперезаписываются. Истории/цены/описания/фото разныхadsотдельны. Фотопризнакиневычисляются.
