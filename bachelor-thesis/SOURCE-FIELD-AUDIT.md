## Конкретные исправления рекомендации

1. source_region/source_property_category не считать обязательными без проверенного сценария использования конкретным сборщиком; не переносить предположение в БД. Не утверждать, что внешних кодов вообще нет: у Циан они реально обнаружены.
2. Контракт должен принимать только конкретное предложение, а не свёрнутую выдачу планировок/диапазонов. Номер квартиры и опубликованные части адреса сохраняются в адресе, разные известные номера не замалчиваются.
3. Сохранять значения из определённых блоков карточки: текущую цену вместо перечёркнутой/ипотеки/цены за метр; объявленную площадь отдельно по смыслу от текста и секции проверки реестра.
4. Не заявлять проверку автоматического снятия, межплощадочного matching и pHash по одному просмотру. История источника не выдаётся за наши прошлые измерения.
5. Прежний FINAL-DATABASE-PROPOSAL.md не является финальным проверенным на источниках проектом; его требуется переработать по этим фактам, сохраняя неподтверждённые решения предложениями.

Не проверены все регионы, категории и виды сделок, все поля всех сайтов, сигналы снятия, реальные пары одной квартиры между площадками, качество matching. Наличие этих границ нельзя заменять высокой оценкой бумажного проекта. Доказательства: свежие HTTPответы, разобранный сохранённый HTML, текущие DOMнаблюдения browser-observations.json. Для DOM JSON честно указано, что он составлен по результатам инструмента, а не сыройAPIэкспорт.
