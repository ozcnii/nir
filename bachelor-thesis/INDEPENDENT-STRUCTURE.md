# Структура модульного монолита

Пункт 1 принят. Система состоит из двух предметных модулей в одном проекте Django с общей базой PostgreSQL.

| Путь в `implementation/` | Ответственность |
|---|---|
| `app/catalog/` | Недвижимость, объявления и цены, сопоставление, предметные записи и выборки, источники и справочники |
| `app/collection/` | Чтение страниц через Playwright, адаптеры источников, нормализация и команда Django `collect` |
| `app/config/`, `app/manage.py` | Настройки, корневые маршруты и штатная точка входа Django |
| `compose.yaml`, `docker/` | Локальные сервисы `app` и `db`, контейнерный образ и профиль Chromium |
| `tools/`, `tests/` | Команды разработчика и сквозные проверки |

## Граница приложений

`collection` читает параметры через публичную выборку каталога и передаёт результат нормализации как контракт P3 в `catalog.publications`. Сборщики принимают простые данные и обращаются к внешним страницам. `catalog` не зависит от `collection`. PostgreSQL-блокировка одного запуска согласует сбор с удалением из справочников и не меняет границу предметных данных.

Для одной карточки сборщик получает опубликованные поля и URL фото, нормализация подготавливает P3, каталог находит публикацию по источнику и внешнему идентификатору. Для новой публикации он сопоставляет недвижимость или создаёт новую запись. Повтор обновляет ту же публикацию, сохраняет её `property_id` и добавляет запись истории только при изменении пары суммы и вида цены. Предложения разных площадок и типов сделки сохраняются отдельно. Сопоставление работает по структурным признакам и тексту без обращений к сети и ORM.

## Интерфейсы

Проект предусматривает общие выборки для каталога, карточки и JSON. Выборка кандидатов для сопоставления принадлежит `catalog.matching_queries`. Штатный Django admin отвечает за вход, источники и справочники. Сбор выполняется из терминала через `collect`; оператор останавливает его по SIGINT/SIGTERM и видит служебный вывод в терминале и Docker. Служебных ORM-моделей в `collection` нет.

Команды, доступные в локальном срезе, приведены в [руководстве реализации](../implementation/README.md). Границы данных, слоёв и экранов описаны в [пункте 2](DB-POINT2-VERIFIED-DRAFT.md), [пункте 8.3](QUALITY-8.3-PROPOSAL.md) и [пункте 5](SCENARIOS-SCREENS-PROPOSAL.md).
