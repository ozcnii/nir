| Вопрос | Рекомендуемый вариант | Альтернатива и последствие |
| --- | --- | --- |
| Устройство приложения | Одно веб-приложение с отдельными модулями сбора, обработки, хранения и интерфейса | Отдельные сервер и клиент дают больше независимости, но требуют двух приложений и отдельного контракта между ними |
| Технологии | Python 3.13, Django 5.2, PostgreSQL 17; пользовательские страницы на шаблонах Django, служебные функции на его административном интерфейсе | TypeScript с отдельными сервером и клиентом; отдельная разработка форм, авторизации и управления данными |
| Получение страниц | Отдельный модуль для каждой из трёх площадок с общим форматом результата; HTTP для подходящих страниц, браузер для динамических | Один универсальный парсер сокращает начальный код, но смешивает различия трёх площадок в одной реализации |
| Модель предметной области | Различать физический объект, публикацию площадки и условия сделки; историю хранить по публикациям, объединение выполнять без потери исходных данных | Одна общая запись на объект упрощает таблицы, но затрудняет сохранение разных цен/сделок/источников |
| Сопоставление | Объяснимые правила по характеристикам и фото, оценка уверенности и отдельная обработка спорных случаев | Обучаемая модель требует отдельного обучающего корпуса и делает объяснение решения сложнее |
| Интерфейс | Каталог и фильтры; карточка со всеми источниками и ценами; история; управление сбором/источниками/справочниками; экран исправления групп | Исправление через служебные формы уменьшает отдельный интерфейс, но делает разбор спорных групп менее наглядным |
