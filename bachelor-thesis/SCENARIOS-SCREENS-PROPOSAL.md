## Роли и путь пользователя

Предлагается две роли: посетитель просматривает каталог и JSON без регистрации; администратор после штатного входа Django управляет сбором, источниками и справочниками. Самостоятельную регистрацию и личный кабинет не добавляем.

Посетитель: выбрать сделку/категорию и фильтры → получить список недвижимости → открыть объект → сравнить публикации площадок и историю цен → перейти к исходному объявлению либо получить те же данные как JSON.

Администратор: войти → задать область обхода → запустить → видеть состояние и счётчики → при необходимости остановить → посмотреть причины ошибок и итог → повторно запустить по принятым правилам4.3.

## Смысл отображения и проверки сценариев

- Каталог показывает одну строку/карточку на property_id. Условия сделки, категории публикации и цены удовлетворяет одна конкретная ads; не собирать подходящий результат из разных публикаций. Общие характеристики берутся из properties. По умолчанию поиск по активным публикациям, снятые сохраняются в карточке/истории.
- Тип объекта в интерфейсе не равен новой таблице: квартира+market_segment=resale/new_build даёт вторичку/новостройку; комната/дом из property_types. Неизвестный market_segment не угадываем: фильтр конкретного сегмента его не пропускает, общий каталог квартир доступен через сброшенную категорию.
- Цены продажи, месяца и суток не объединяются в одну общую сумму или общую линию истории. История и last-known цена принадлежат отдельной ads; «от» отображается явно. При отсутствии пригодной новой цены показывать последнюю известную с датой её наблюдения, без обещания актуального тарифа. Если цены никогда не было — «Цена не получена»; ценовой фильтр такую ads не пропускает.
- Один объект с двумя площадками: пользователь видит общие площадь/комнаты/этаж, затем две отдельные публикации с собственными описаниями, фото и историями. Ручного merge/split или перезаписи характеристик не предлагается.
- Фото отображаются по опубликованным URL; ошибка внешней картинки даёт понятную заглушку, не загрузку на наш сервер/расчёт хеша. Обнаруженные относительные фотопути нормализуются по принятым правилам4.2 через реально опубликованный полный URL.
- Каталог: пустая БД, отсутствие совпадений, ошибочный диапазон/формат фильтра, обычная пагинация. Карточка: неизвестные поля, нет цены/истории/фото, недоступная картинка, все публикации сняты, неизвестный property_id. Пустой результат отличается от ошибки загрузки нашего приложения.
- Управление: источник выключен, сбор уже идёт, запрос остановки, завершение с пропусками/ошибками, сбой и повторный запуск. Остановка и счётчики подчиняются4.3; доступность отдельной страницы админки не доказывает работоспособность runner.
- Источники/справочники: изменения применяются к следующему запуску, текущая область сбора фиксируется на старте. Никаких новых постоянных параметров/таймаутов в предметной БД. Параметры текущего обхода — вход уже предусмотренного runner; их форма/хранение служебного состояния пока не реализованы. Журнал использует существующий запланированный механизм; смена запуска не подразумевает новую доменную таблицу.
