## 1. Маршруты

| Назначение | Предлагаемый маршрут | Доступ/метод |
|---|---|---|
| Корень | / → /catalog/ | GET, переход к каталогу без отдельной главной страницы |
| Каталог | /catalog/ | GET, без регистрации |
| Карточка | /properties/<id>/ | GET, без регистрации; id — наш properties.id |
| JSON каталога | /api/properties/ | GET, те же фильтры/страница, без регистрации |
| JSON карточки | /api/properties/<id>/ | GET, все сохранённые ads объекта |
| Административная главная/вход | /admin/ и /admin/login/ | Штатный Django admin/auth |
| Выход | /admin/logout/ | Штатная форма выхода Django, POST |
| Экран сбора | /admin/collection/ | GET, административные права |
| Запуск / остановка | /admin/collection/start/ и /admin/collection/stop/ | POST, административные права; GET не меняет состояние |
| Журнал | /admin/collection/logs/ | GET, административные права |
| Источники и справочники | Штатные разделы зарегистрированных моделей внутри /admin/ | Формы/ссылки генерирует Django; отдельные дублирующие CRUD-страницы не добавляются |

Последняя строка означает готовые маршруты Django для Source/Region/PropertyType, а не произвольные ручные URL поверх моделей. При реализации URL строятся через штатные имена маршрутов по фактическим классам моделей; отдельный выбор технического написания имени класса не меняет экран/схему и не выдаётся за уже существующий код. Сбор/журнал — собственные служебные представления предусмотренного collection.admin под защитой стандартного админ-сайта. Конкретный порядок регистрации custom URL должен исключать перехват штатным admin catch-all.

Гость при обращении к управлению — на вход; вошедший без нужных административных прав — отказ403. Все действия изменения — POST и штатная защита форм Django; «выключить источник»/«удалить запись» не исполняются открытием ссылкиGET. Удаление справочников при активном/ещё не остановленном сборе запрещено сервером по принятому5.4. «Остановить» относится к показанному служебному идентификатору запуска: устаревшая вкладка не должна останавливать другой уже начатый запуск, вместо этого сообщение об изменившемся состоянии и обновление страницы. Это детализация привязки действия к уже предусмотренному запуску, не новая таблица.

## 2. Фильтры и JSON

Общие входные параметры каталога/егоJSON: deal_type(sale/month_rent/day_rent),category(all/flat/resale/new_build/room/house),region_id;price_min/max,area_min/max,rooms_min/max,floor_min/max,page. Это наши значения интерфейса, не коды источников. «Любая» передаётся all или отсутствующимcategory; flat — квартиры любого сегмента. По умолчанию sale,page1,page_size20,порядок properties.id по возрастанию. Размер страницы20фиксирован принятым каталогом, произвольный page_size клиента не добавляется. Все значения валидируются общим разбором фильтров, а не двумя разными правилами HTML/API.

JSON каталога: объект с count(число уникальных подходящих объектов),page,page_size,next,previous,results. next/previous — ссылка того же API с теми же фильтрами и нужной страницей либо null. results — текущая страница объектов, каждый содержит id,region,property_type,address,latitude,longitude,area_m2,rooms,floor,floors_total,land_area_m2 и массив ads. В каждомads списка: id,source_code,external_id,url,deal_type,market_segment,is_active,observed_at,photos,photos_observed_at,latest_price. description и полная price_history остаются в детальномJSON, а не обязательны в кратком списке. region/property_type — id/name уже существующих справочников, без новых колонок. latest_price — null либо price_rub/price_kind/observed_at, вычисленные из последней строки истории, не новая колонкаads.

Сначала условия сделки/сегмента/цены удовлетворяет однаads, затем группировкаproperty_id и пагинация уникальных объектов. В JSON каталога ads только прошедшие фильтры, как в принятой выдаче. При типе квартирыflat отсутствует требование известногоmarket_segment; комнаты/дома не включаются.

JSON карточки: те же свойства плюс всеads, включая снятые/не прошедшие фильтры каталога. Каждаяads дополнительно содержит собственные description и price_history. История — строкиobserved_at,price_rub,price_kind в хронологическом порядке. is_active остаётся сохранённым состоянием, не обещанием текущей доступности источника. Цена/тип сделки/история никогда не агрегируются между публикациями.

Сериализация по принятому контракту: деньги/площади/координаты — decimal-строки; идентификаторы собственныхPK и счётчики — числа; external_id — строка; неизвестное — null; фото и история — массивы, пустые[]при отсутствии записей. Даты — ISO8601UTC. Фото — URLстроки, безхешей/метаданныхпланировок; описание — текст. Недоступная новаяцена сохраняет прежнюю историю/дату;latest_price.observed_at — дата фиксации изменения,не время последней проверки объявления. photos_observed_at — время получения списка,не проверка самих файлов.

## 3. Макеты блоков для согласования

Это текстовые макеты, не готовый визуальный дизайн и не прошедший проверку интерфейс.

### Каталог

| Зона | Расположение |
|---|---|
| Верх | Название «Каталог недвижимости», ссылка управления/входа |
| Под верхом | Строка сделки/категории/региона; строка числовых диапазонов с единицами и пояснением последней известной цены |
| Под фильтрами | «Найти»,«Сбросить»,«JSON»; число найденных объектов |
| Основная область | Вертикальный список: превью слева; адрес/общиехарактеристики и отдельные предложения площадок справа;«Открыть объект»/«На площадку» |
| Низ | Назад/вперёд и текущая страница; фильтры сохраняются |

На узком экране фильтры и блоки перестраиваются в одну колонку, единицы/«от»/даты не исчезают. У дома отдельно участок, у комнаты площадь/число предлагаемых комнат; неизвестные признаки не становятся нулём.

### Карточка недвижимости

Верх: «Назад к результатам» при контексте поиска или «В каталог» при прямом входе;«JSON». Затем заголовок/адрес/общиехарактеристики. Ниже вертикально активныеads: площадка/сделка/сегмент → последняяизвестнаяцена+дата → собственнаягалерея → описание → таблицаистории. Внизу раскрываемые«Снятые объявления(N)»с теми же блоками. Истории и галереи не смешиваются. При входе из поиска подходящиеads имеют принятуюпометку,остальные не скрыты.

### Администрирование

ШтатнаяоболочкаDjangoadmin. Вход — короткаяформа. Сбор — областьзапуска сверху; затемдействия; затемстатус/этап/счётчики/ссылка нажурнал. Источники — списокпереключателейenabled. Справочники — штатныесписки/формы. Журнал — выборзапуска/источника/уровня сверху, затемсписоксобытий,итог/«Обновить». Принятыйсерверныйзапретудалениявиденкакнедоступноедействие с объяснением. Дополнительных«дашбордов»,вкладокснеописаннымифункциямииинструментовручногослиянияне добавляется.
