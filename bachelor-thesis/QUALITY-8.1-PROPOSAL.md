## 1. Основа и существующие механизмы

Приняты Python/Django/PostgreSQL, два приложения catalog/collection и Django templates. Требование владельца — готовые практики качества, линтинг/форматирование, отдельные правила кода и агентов. НИР не предписывает конкретные инструменты этой таблицы: это наши предложения.

В репозитории уже есть npm/Playwright для снимков аналогов при оформлении пояснительной записки. Python-приложения, pyproject.toml/uv.lock и проектных проверок приложения пока нет. Существующие снимочныескрипты не объявляются его браузерными тестами; сами по себе они не заменяют тестовый Python-контур. Старый TECHNICAL-DESIGN.md содержит исторические непринятые/отвергнутые варианты; источники текущей структуры — INDEPENDENT-STRUCTURE.md, PLAN.md и актуальные принятые спецификации.

Факты инструментов перепроверены по документации авторов: [QUALITY81-PRIMARY-SOURCES.md](evidence/QUALITY81-PRIMARY-SOURCES.md). Ни выбор инструмента, ни список команд не означают проверенную совместную конфигурацию.

Ruff/mypy/djLint — инструменты разработки. Django и Playwright требуются самой программе: Playwright нельзя спрятать только в dev-зависимости, ведь его использует collection. Браузерные бинарныефайлы и системные зависимости требуют отдельной установки/контроля версии; наличиезаписи вuv.lock не означает, что браузер установлен.

## 3. Почему такой состав и какие есть альтернативы

- Ruff закрывает lint/формат/импорты без трех параллельных инструментовBlack/flake8/isort для техже ролей. Это наш выбор сокращения дублирования, не обязательное правило Django.
- Для обычных Django-тестов можно выбрать pytest/pytest-django, но рекомендуем встроенный runner: нужные механизмы уже предоставляет принятый фреймворк. Дополнительный runner сам по себе не улучшает содержательность тестов.
- Авторы Playwright рекомендуют pytest-plugin для end-to-end, но документируют и отдельную Python-библиотеку. В этом варианте браузерные сценарии предлагается запускать через существующий Django/unittest-контур с Python API, не устанавливать второй runner только из-за рекомендацииplugin. Для тестового сервера используются штатные LiveServerTestCase/StaticLiveServerTestCase Django вместе с библиотечным API Playwright; отдельный самописный сервер не нужен. Настройки жизненногоцикла и конкретная интеграция оформляются далее, runtime сейчас не проверялся.
- mypy/django-stubs и djLint дополняют Ruff: типовые контракты ORM и Django-шаблоны — другие риски, а не второй Python-линтер.
- uv выбран как готовый менеджер с lockfile. Роли менеджера и форматтера не смешиваются; старый npm/package-lock для документных скриптов не заменяем и не переобъявляем частьюPython-пакета.

## 4. Что реально нужно проверить перед включением

Перед фиксацией версий выбрать совместимую связку Python/Django/mypy/django-stubs по таблице авторов, различая полную иpartialподдержку. Текущая матрица приведена как источник в evidence, а не как уже выбранныеpins. Последние версии всехпакетов не объявляются автоматически совместимыми. plugin проверяется с подходящими settings приложения; возможность загрузить Django не равна доказательству корректности ORM/транзакций.

Далее специфицируется единый профиль Ruff/mypy/djLint, чтобы локально/вCI не работали разные правила. Для проверки неизменяемости файлов используются check-режимы; форматирование/исправления — отдельное явное действие с просмотром diff. Фиксацияпрофиля не должнапереформатировать исторические свидетельства/нормативныеисточники вместо кода.

Для иллюстрации ролей, не команды к запуску сейчас: ruff check; ruff format --check; mypy с Django-plugin; djlint --lint и отдельно --check с django-профилем; manage.py check/test; manage.py makemigrations --check. Последняя команда уже подразумеваетdry-run, не создает миграции и не доказывает применимость схемы к существующейБД. check --deploy относится к подготовке релизныхsettings, не ко всем изменениям.

Политика правил/строгости/подавлений — следующий подпункт8.2; отдельныеCODING/AGENTS — проектные правила, не самописныезамены инструментов. Git hooks/CI обсуждаются после утверждения состава и профиля. Восьмой пункт не объявляется полностью готовым по одной таблицеинструментов.

## 5. Границы и ожидаемое решение владельца

Для8.1 предлагается выбрать этот набор ролей целиком: uv, Ruff, mypy+django-stubs, djLint, штатныеDjango-проверки и PlaywrightPython. Не выбираем сейчас дополнительные JS-инструменты/очереди/новые продуктовые функции; при появлении конкретной JS-задачи ее покрытие уточняется отдельно.

Конкретные версии/Python-ветка, наборы правил, строгость, длина строки и код конфигураций еще не утверждены; они будут показаны отдельными решениями до установки/реализации. Кодовыйстиль, правила агентов и автоматическийзапуск не забыты, а следуют отдельными подпунктами8. Линтер/типизация/тесты не обещают отсутствиеошибок и не заменяют реальные UI/source-сценарии7.1 или исследование7.2–7.4.

Оценка критика — только проверка этого предложения. Владелец принял инструменты8.1; совместнаяработоспособность набора еще не проверена на приложении.
