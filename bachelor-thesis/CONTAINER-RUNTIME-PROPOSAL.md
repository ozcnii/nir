# Пункт 9 — порты, пользователь app и Chromium

## Сеть и сервисы

| Область | Настройка |
|---|---|
| Адрес сайта | `http://127.0.0.1:8000` по умолчанию. Django слушает порт `8000` внутри контейнера. На хосте порт опубликован только на loopback. |
| Другой порт | Если порт занят, оператор задаёт свободный `APP_PORT`. В изолированной проверке `APP_PORT=0` поручает Docker выделить порт, его значение читается через `docker compose port app 8000`. |
| PostgreSQL | `db:5432` в сети Compose. Порт на хосте не опубликован. Данные хранятся в томе `db`. |
| Пользователь Linux | `app`, UID/GID `10001:10001`, домашний каталог `/home/app`. У PostgreSQL собственный пользователь образа. |
| Процессы | `init: true` в сервисе `app`. Docker init передаёт сигналы и собирает завершившиеся дочерние процессы. Для `app` задан `stop_grace_period: 60s`. |

Сайт и база — два постоянных сервиса. Django перед запуском web проверяет миграции через `migrate --check`. Сбор выполняется отдельным контейнером на том же образе `app`. Роли PostgreSQL и порядок старта описаны в [спецификации первого запуска](FIRST-LAUNCH-ROLES-PROPOSAL.md).

## Сборка и работа Chromium

Системные зависимости и bundled Chromium версии закреплённого Playwright устанавливаются при сборке образа. Используются `channel=chromium`, `headless=true` и `chromium_sandbox=true`. Бинарники размещены в `/ms-playwright`. Chromium запускается под непривилегированным пользователем с [профилем seccomp](../implementation/docker/README.md). Ошибка запуска sandbox возвращается как ошибка сбора. Внешние порты отладки не публикуются. Для временных данных используется `/tmp` со штатными настройками Chromium и Playwright.

Команда сбора создаёт собственные браузер и контекст, закрывает их при выходе и передаёт снимок каталогу. Ход и ошибки доступны в выводе Docker. Каталог хранит URL фотографий. [Запуск и остановка](PROCESS-LIFECYCLE-PROPOSAL.md)

## Проверяемые сценарии

- Фактический адрес на loopback, доступ к `db:5432` и отсутствие публикации порта PostgreSQL на хосте.
- Запуск Django и Chromium под UID/GID `10001:10001`, доступ к браузеру и временным путям, работа sandbox на проверяемой платформе.
- Завершение команды по сигналу с сохранением работоспособности сайта и состояния PostgreSQL.
