## 3. Точное условие присоединения новой публикации

### Повтор уже известной публикации — предлагаемое уточнениеP4

Общий порядокP5 сохраняется: валидный конверт, stale/ignored по времени, затем совместимость и только после неё изменения. Для нового времени перед обновлениемads.description/прочих данных и любым patch сравнивается предлагаемая физическая единица с текущейproperties:

- Явная смена физического вида, известного числа предлагаемых комнат(1↔N, N↔M), установленного дома/квартиры/комнаты не принимается молча: conflict с диагностической причиной смены предлагаемой единицы; прежниеads/properties/связи/цена/фото/observed_at остаются неизменными. Причина — существующая диагностика результата/журнала, не новая колонка.
- НовыйNULL не стирает ранее известный rooms/адрес и не объявляется сменой единицы. Неизвестное→однозначно известное допускается прежним совместимым patch; набор никогда не превращается в одиночную комнату за счёт сброса количества вNULL.
- Полный комнатный адрес для будущего присоединения нельзя получить склейкой разрозненных номеров. Ключевые компоненты одной цепочки квартиры/комнаты должны быть явно опубликованы вместе в одном принятом снимке. Адресный patch добавляет такую целостную цепочку только при совместимости с уже известными компонентами; известные части/район не теряются. Если из частичного нового адреса область номера не ясна, положительного комнатного ключа он не создаёт.
- При наборе с тем жеN состав по имеющимся полям не восстанавливается. Повтор(source,key) обновляет эту же отдельную публикацию/её предложенную единицу; невидимую смену конкретных членов набора не обещаем обнаружить. Межплощадочно наборы не присоединяются, поэтому такое неизвестное изменение не переносится на чужиеads. Явный конфликт адреса/числа/вида всё равно отклоняется.

Это новое предложение к обработке повторов комнат, а не уже принятое исключение. Нет split/rebind/ручного исправления и новых полей.

### Новая публикация

Для НОВОЙ публикации:

1. Предложение и сохранённаяproperties однозначно означают одну комнату, rooms=1. Набор, rooms=NULL и rejected-снимок сюда не проходят.
2. Выбор предварительных кандидатов: тот же region_id, property_type_id=комната, один однозначный населённый пункт, улица/дом/корпус. Пропущенный корпус не угадывается. Это только отбор, а не решение об идентичности.
3. Положительная идентичность: у обеих сторон опубликован и полностью совпадает адрес именно комнаты — включая номер квартиры И номер комнаты в ней(либо явно опубликованный адресный номер комнаты как отдельной единицы дома). Номер квартиры один не годится. «Комната1» из порядка фотографий/планировки/списка не становится адресным номером. Номер хранится как опубликованная часть существующего address с явными обозначениями «квартира…», «комната…» и их областью; нового room_id/таблицы нет. Голое «№1» сохраняется только в опубликованном виде и не участвует как номер комнаты; нормализация/повторный разбор не повышают его определённость. Для цепочки квартиры/комнаты не допускаются разные комнаты одного дома из-за потерянного номера квартиры. При неустранимо неоднозначном повторном разборе — отдельнаяproperties, не attach. Проверенных номеров таких комнат в текущей контрольной паре нет: правило не обещает их массовую доступность. Если роль/область номера неоднозначна, положительной идентичности нет.
4. Перечень физических проверок конечный: area_m2, floor, floors_total, rooms. Сравниваются только общие известные поля; все общие значения должны точно совпасть после принятой нормализации. NULL не считается совпадением/противоречием. Для положительного результата хотя бы одно из area_m2/floor известно у обеих сторон и совпадает. rooms=1 — условие допуска, а не дополнительное доказательство. Координаты не доказывают комнату и не имеют произвольного допуска; land_area_m2 для комнаты не участвует. Разные явные адресные номера дают отказ.
5. Полный seller-текст не является заменой номера комнаты. Он и публичный артикул могут использоваться для исследовательской сверки, но не разрешают attach при отсутствии опубликованного комнатного адреса. Артикул537953 в реальной паре проверен как «Номер объекта», его зерно/уникальность именно комнаты не подтверждены — он не превращается в room_id.
6. Посчитать properties, прошедшие ВСЕ условия2–4. Ровно одна — attach. Ноль либо более одной — отдельнаяproperties. Много предварительных кандидатов одного дома не запрещает присоединение, если ровно одна прошла положительное правило. Не выбирать первыйID.
7. После attach действует только прежний patch: не затирать известное NULL, дополнять неизвестное совместимым; не перезаписывать известную площадь. Истории разныхads раздельны. Фото толькоURL, без хешей/анализа. Никаких ручных исправлений.

Это существенно ограниченная, воспроизводимая дедупликация комнат. Даже адресный номер из объявления может быть ошибочным; нулевая вероятность ошибки не обещается. Однако шаблонный текст больше не является достаточным основанием склейки, и отсутствие номера не интерпретируется как совпадение. Без опубликованного различающего признака две одинаковые комнаты принципиально не различаются по имеющимся полям.
