## Детализация правил

### Адрес

1. Брать опубликованные части адреса основной карточки; номер квартиры/подъезда — только из блока именно предлагаемой единицы. Город в шапке сайта, геолокация браузера и соседние предложения не источники адреса.
2. Сжать пробелы, нормализовать Unicode NFC. Раскрывать только распознанные обозначения компонентов: ул.→улица, просп.→проспект, пер.→переулок, кв.→квартира. Для сравнения регистр и ё/е несущественны; опубликованное написание имени сохраняется для показа. Не заменять подстроки внутри названий.
3. Сохранить буквенные суффиксы, дроби, дефисы, корпус/строение/номер квартиры/подъезд. Дом 7а не равен 7; «Дом 7А» как маркетинговое название корпуса не доказывает адрес «дом 7, корпус А». Не угадывать недостающие части.
4. region_id — наш справочник субъекта РФ. Явный субъект карточки сопоставляется с regions.name. Если опубликован только город, разрешена только заранее проверенная однозначная привязка; для текущей выборки Самара→Самарская область подтверждается адресами самих карточек Циан. Это ограниченная конфигурация адаптера, не универсальное определение субъекта по названию города. Одноимённый/неустановленный населённый пункт без субъекта → обязательный регион не определён, снимок rejected. Новую таблицу географии или внешний геокодер не добавляем.
5. Частичный адрес сохраняется как частичный. «Самара, район Советский» не превращается в полный дом и не проходит A/B. Правила дополнения известного адреса остаются принятыми в пункте 3.

Реальный пример: Циан333842107 «Самарская область / Самара / р-н Ленинский / ул. Буянова / 120» и Домклик2080269220 «Самара, улица Буянова, 120» → одинаковые компоненты улица Буянова, дом120, населённый пункт Самара; region_id субъекта Самарская область. Квартира неизвестна, не подставляется. В address можно сохранить район, но отсутствие района у второй площадки не противоречие. Район не заменяет населённый пункт или дом.

### Числа и единицы

Сначала установить смысл и блок значения, затем преобразовать запись. Группирующие обычные/неразрывные пробелы удалить в числе, десятичную запятую заменить точкой. Разбирать строку точным Decimal, без промежуточного float. Цена — рубли, площадь — м². Сотка=100м², гектар=10000м². Иные валюты без согласованного пересчёта не выдаются за рубли: цена unavailable. Цена за м²/ипотечный платёж/залог не заменяют общую цену.

Для принятых decimal(...,2) значения с более чем двумя значащими дробными знаками после перевода единиц не округлять молча: структурное значение не прошло разбор → rejected; непригодная цена → unavailable. Координаты, если достоверно получены именно для объекта, приводить к семи знакам Decimal с ROUND_HALF_EVEN и проверять диапазон/парность по принятому контракту; отсутствие координат → оба NULL. Точность координат не служит основанием объединения квартир.

Этаж и этажность — отдельные целые из однозначной пары «12 из20». Диапазон «2–14» не превращать в этаж2. Для одноэтажного дома этажность1, этаж помещения NULL. Для комнаты area_m2 — площадь продаваемой комнаты; rooms — число предлагаемых комнат, не комнат всей квартиры. У явного предложения одной комнаты rooms=1. Количество спален/спальных мест не приравнивать к rooms. Для студии0 — только при явной метке студии. Отсутствие не заменять нулём.

### Описание

В ads.description сохранять полный текст продавца с абзацами; нормализация для сравнения не портит исходный текст показа. Короткое превью не дублировать. Кнопки/баннеры отбрасывать по отдельным узлам интерфейса, не глобальным удалением слов «Скрыть»/«Читать далее» из seller-body. Только описание ЖК → нет индивидуального description, B не выполняется.

Временный ключ сравнения: NFC, регистр→нижний/casefold, ё→е, эквивалентные типографские кавычки→одинаковые, повторные пробелы/переносы→один пробел. Явные декоративные маркеры/эмодзи в позиции оформления заменять пробелом, сохраняя границы слов; цифры/значащие символы внутри чисел не удалять. Десятичная запятая между цифрами→точка только в однозначной записи величины; разделитель списка не превращать в десятичный знак. Неоднозначное оформление оставлять различным, не «чинить» догадкой. Не менять слова, отрицания, размеры, порядок текста; синонимов/процента похожести нет. Это детализация принятого строгого сравнения, не новая модель matching.

Реальная пара Буянова: повторное открытие подтвердило наличие отдельных seller-блоков. Прежний протокол matching-url-only-checks.json сообщает о равенстве текстов после прежнего удаления оформления, но не доказывает работу всех предлагаемых здесь преобразований. В доказательствах4.2 нет двух полных текстов и воспроизводимого применения нового набора операций: строгая эквивалентность по новому правилу остаётся непроверенной. Не выдаём этот пример за успешно выполненный тест4.2; реальными примерами преобразований ниже служат непосредственно прочитанные адреса, числа и единицы.

### URL и неизвестные значения

external_id/source_code — уже принятый контракт; не извлекать квартиру/тип из одного URL при противоречии содержимого. Фактический URL карточки сохраняется. Фотоссылки сохраняются опубликованными, включая параметры; не менять расширение, размер или подпись CDN. Убирать только точные повторы одинаковых URL. Область — основная галерея, без рекламы/соседей. Общий счётчик слайдов не равен количеству фото. Опубликованную планировку из основной галереи можно хранить как URL без новой сущности; не добавлять промо-слайды.

Отсутствие seller-description, явное NULL и ошибка извлечения различаются тем же правилом; нельзя ошибку разбора выдавать за отсутствие. Снятие подтверждается отдельным явным состоянием сайта.
