# Пункт 1 — разделение ответственности, актуальное предложение

Статус: разделение НЕ принято. Реализация не начата. Пользователь принял простой повторный запуск сбора без дублирования записей и исключил ручное исправление дублей. Предыдущие оценки решений с координатором и ручными исправлениями к этому варианту не применяются.

Предложение: три модуля одного Django приложения, одна PostgreSQL.

1. collection: получение выдачи/карточек с трёх источников, специфичный разбор источника, HTTP/браузер, сетевые ошибки, запуск/остановка/журнал сбора. Возвращает исходные значения, происхождение/идентификатор и ссылки на фото. Не нормализует общие предметные значения, не решает тождество объектов.
2. catalog: сохранение исходных и нормализованных наблюдений; общий формат адресов, площадей и цен; публикации, сделки, объекты, история; ссылки/состояние/версия содержимого фото; поиск, карточки, JSON. Единственный владелец записи принадлежности публикации объекту. Приём одного наблюдения идемпотентен по идентификатору операции; новая проверка источника — новое наблюдение. Ошибка нормализации не удаляет исходные сведения и прошлую успешную версию.
3. matching: получение нужных фото в память по входным ссылкам, расчёт признаков с версией и checksum, отбор кандидатов, сравнение и объяснение автоматического решения. Постоянно не сохраняет оригиналы. Возвращает результат на конкретных входных версиях; не переписывает объявления/цены/членство каталога. Производные признаки принадлежат matching, сведения об исходных фото — catalog.

Явная последовательность в команде запуска, без отдельного координатора/собственной очереди: collection получает → catalog сохраняет/нормализует → matching рассчитывает → catalog проверяет актуальность входов и применяет автоматическое решение. Каталог не запускает matching скрытым сигналом. Команда связывает операции, не содержит правил нормализации/сопоставления. Объекты без уверенного совпадения сохраняются раздельно; ручного экрана/исправлений нет.

Повтор после закрытия программы: сбор запускается заново. Идентичность публикации по (источник, внешний ID); повтор одной операции не дублирует наблюдение. Незавершённое сопоставление проверяется в начале/конце запуска по сохранённому состоянию версии обработки, в том числе если конкретная карточка больше недоступна; для него используются уже сохранённые данные. Это признак незавершённой обработки, не универсальная очередь с собственным исполнителем. Внешняя недоступность не стирает сохранённые сведения. Фото могут стать недоступны, результат сравнения тогда использует доступные признаки либо остаётся неопределённым; точные правила алгоритма — следующий шаг проектирования.

Перед применением catalog проверяет версии использованных наблюдений/признаков и состояние членства в короткой транзакции. Предлагается один активный проход автоматической обработки; параллельный старт отклоняется. Точный механизм блокировки и правила перерасчёта после изменения входов отдельно проектируются после выбора границ. Ручных правок групп нет; конкуренция между сбором и сопоставлением всё равно должна учитываться. Сетевые вызовы вне транзакции. Результат сравнения/его применение разделены, поэтому сбой после расчёта не теряет исходные сведения.

Разделение не задаётся количеством таблиц/файлов: catalog может содержать внутренние файлы нормализации/хранения/представлений; это разные задачи внутри одного владельца данных. Если растёт сложность, пересмотр границ сначала предлагается пользователю. Никакой новый инфраструктурный выбор этим документом не принят.

Оценивать готовность предложения о границах, не реализацию, полный алгоритм, интеграции или ВКР целиком. Важные вопросы для оценки: не смешано ли владение исходными фото и производными признаками; можно ли повторить незавершённый этап без новой загрузки карточки; нет ли скрытой отдельной системы задач; единственный ли владелец членства.
