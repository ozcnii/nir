## Вход и доступ

Штатный вход/выход Django: логин, пароль, «Войти»; неверные данные дают понятное сообщение. Самостоятельная регистрация и собственная таблица ролей не добавляются. Управляющие экраны и действия доступны только пользователю с административными правами, проверяемыми сервером, а не только наличием кнопок. Гость при прямом открытии перенаправляется на вход; пользователь без нужных прав получает отказ доступа. Конкретный список учётных записей не создаётся этим проектированием.

Предлагается обычный просмотр каталога/карточки без регистрации, как ранее предлагалось в общем составе экранов; это часть принятого5.4, а не уже разрешённое публичное развёртывание приложения. После входа доступна единая навигация «Сбор / Источники / Справочники / Журнал» и «Выйти». Выход из учётной записи/закрытие страницы не останавливает отдельный запущенный runner; остановка выполняется явным действием5.1/4.3.

## Сбор данных

До старта форма: выбранные включённые источники, регионы, категории и сделки — принятие5.1.30секунд и один повтор показываются как фиксированные правила, не редактируются. Кнопки «Запустить», «Остановить», «Обновить состояние», «Открыть журнал».

Перед запуском проверять непустые/поддержанные значения и источник enabled; ошибка отмечается в форме, запуск не создаётся. Неподдержанный маршрут не изображается проверенным. Серверная блокировка одного сбора сохраняется; двойной клик/вторая вкладка не запускают второй обход, пользователь видит уже работающий запуск.

При запуске показать фиксированный снимок области и служебный идентификатор запуска, текущий источник/этап, число уникально обработанных публикаций и результаты добавлений/обновлений/без изменений/пропусков/ошибок. Служебный идентификатор/счётчики принадлежат runner/журналу, не таблице collection_runs. Процент полной базы площадки не выдумывается из этих счётчиков.

Пока идёт запуск, его область не редактируется; «Запустить» недоступна, «Остановить» доступна. После нажатия состояние «Остановка запрошена», новые остановки не плодят задания; окончательная остановка — только после подтверждения runner. Завершение текущей атомарной записи и закрытие принадлежащих запуску ресурсов — по принятому4.3. Повторный старт доступен после фактического завершения предыдущего и освобождения блокировки.

Итог: завершён; завершён с пропусками/ошибками; остановлен пользователем; ошибка запуска/выполнения. Рядом причина и переход к журналу. Неизвестное/недоступное состояние исполнителя показывается как неизвестное, не как успех; потеря окна браузера не считается подтверждённым завершением runner. Конкретный способ служебного состояния/передачи остановки входит в предусмотренный runner и итоговый технический проект, не новая предметная таблица.

## Источники

Список только поддержанных источников с понятным названием для интерфейса и переключателем enabled, «Сохранить». Понятная подпись берётся из адаптера/представления по code; колонка sources.name не добавляется. Идентификаторы/маршруты/селекторы не редактируются администратором.

Смена enabled действует на будущие запуски; текущий обход фиксирован5.1. Для немедленной остановки — кнопка на странице сбора. Выключение не удаляет/снимает сохранённые ads. Авито остаётся в конечном объёме, но его текущая отложенная готовность не маскируется активной работоспособностью адаптера; возможность выбрать источник зависит от фактической поддержки при реализации.

## Справочники

Штатные списки/формы Django admin для regions и property_types: список, поиск по названию, «Добавить», «Изменить», «Сохранить»; удаление только неиспользуемой записи по уже принятой защите ссылок и только когда сбор не работает. При занятом названии/пустом имени — ошибка формы, не тихое создание дубля. При используемой записи — понятная причина невозможности удаления.

Отдельное правило прямо принято владельцем17ноября2026: пока сбор работает, удаление любых записей regions/property_types недоступно, включая пока неиспользуемые и невыбранные в этом запуске. При запрошенной, но ещё не завершённой остановке запрет сохраняется. В интерфейсе действие недоступно с пояснением «Идёт сбор: удаление справочников доступно после его завершения». Прямой запрос на удаление отклоняется сервером тем же правилом; скрытая кнопка не является защитой. Это распространяется на одиночное и массовое удаление.

Разрешение удаления проверяется согласованно со стартом: при конкурирующих запуске/удалении сначала завершившееся действие определяет результат. Если запуск уже зафиксировал область и получил блокировку, удаление отклоняется; если запись успела удалиться первой, запуск повторно проверяет выбранные записи и не стартует с несуществующимFK. Проверку нельзя выполнять только при открытии формы или оставлять промежуток между проверкой и удалением. Реализация использует предусмотренное управление/синхронизацию запуска, без новых доменных таблиц/полей. При неизвестном состоянии runner удаление не разрешается до проверки отсутствия активного сбора. После фактического окончания сбора и освобождения блокировки остаётся обычная защита используемыхFK; удаление не выполняется автоматически по ранее нажатой кнопке.

Правило удаления первоначально принято отдельно; позднее владелец явно принял весь5.4,17ноября2026.


ID остаётся неизменяемой ссылкой. Переименование существующего вида не должно превращать сохранённую квартиру в дом; добавление названия не создаёт автоматически коллектор/поддержку маршрута. Возможность выбрать значение при запуске валидируется по5.1. Если требуется смена предметного смысла существующей записи, её нельзя выполнить как исправление подписи — это отдельное предметное изменение, а не скрытое массовое переписывание данных. Политика конкретных полей редактирования уточняется с макетом/правилами справочника без расширения схемы.

## Журнал

Администратор выбирает запуск, при необходимости источник/уровень сообщения; видит область запуска, время события, этап, ключ публикации при наличии, результат и причину ошибки/пропуска, итог. Кнопки «Обновить», переход обратно к состоянию сбора. Пустой журнал явно отличается от ошибки чтения журнала.

Это представление предусмотренного журнала collection, без таблиц runs/logs и без новой очереди. Не давать ручное исправление ads/property_id или цен через журнал; история предметных данных неизменяема. Тексты ошибок передают понятную причину (например, таймаут/непригодное значение/неподдержанный формат), не обещают восстановить отсутствующие поля объявления.

## Критические переходы

- Нельзя запустить со снятым enabled/неподдержанным сочетанием; проверка перед стартом серверная.
- Настройки источника изменены во время сбора — текущий снимок сохраняется, последующий запуск использует новые значения.
- Остановка принята интерфейсом — ожидать подтверждения runner; затем повторный старт начинает обход сначала без дублей по принятому контракту.
- Сервис/БД/runner недоступны — понятная ошибка/неизвестное состояние, данные не выдаются за успешно сохранённые.
- Отсутствие цены/фото в конкретной публикации не равно сбою всей системы; причины обработки доступны в журнале по4.3.
