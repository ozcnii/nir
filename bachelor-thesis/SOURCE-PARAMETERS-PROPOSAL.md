# 5.1. Параметры источников и запуска — принято

17 ноября 2026. Пользователь просит конкретный минимальный вариант с проверкой прежнего критика и отдельного нового чистого. Вариант прямо принят владельцем17ноября2026. Код не пишется. БД и принятые 4.1–4.3 не меняются. После проверок 6.1/6.4 область включает три адаптера: Авито, Циан, Домклик.

## Конкретный вариант

| Где | Что администратор меняет | Зачем | Где значение живёт |
|---|---|---|---|
| Источники | Включён/выключен для каждого уже поддержанного источника | Разрешить/исключить площадку из будущих запусков | Принятый sources.enabled, новых колонок нет |
| Сбор данных, перед запуском | Какие из включённых площадок участвуют сейчас | Запустить одну площадку или несколько | Параметры только текущего запуска |
| Там же | Регион или выбранные регионы из справочника | Ограничить географию текущего обхода | Параметры только текущего запуска; ссылка на существующий regions |
| Там же | Категории: вторичка/новостройка/комната/дом | Ограничить предмет текущего обхода | Параметры запуска; категории переводятся в уже принятые property_types/market_segment, новая таблица не нужна |
| Там же | Сделки: продажа/месячная/суточная аренда | Выбрать нужные предложения | Параметры только текущего запуска; существующие значения deal_type |

Один общий набор региона/категорий/сделок для выбранных площадок этого запуска. Если нужен иной набор для конкретной площадки, администратор выбирает её одну и запускает с другим набором; новый редактор постоянных профилей по источникам не добавляем. Это техническая детализация функции НИР§5.5 «управление списком источников и их параметрами», а не утверждение, что сам НИР предписывает именно такой набор полей.

## Что не является редактируемым параметром этой формы

Уже принятые30секунд на попытку и один повтор отображаются как действующие правила, но не меняются администратором в интерфейсе. Пользователь4.3их уже принял; новые поля таймаутов, интервалы, число потоков, лимиты страниц и новые автоматические расписания не предлагаются. Обход остаётся последовательным.

Адреса маршрутов, способы перехода по выдаче и пути встроенных данных — проверенные механизмы существующих адаптеров, меняемые разработчиком в коде при изменении сайта; это не произвольные настройки через админку. Идентификаторы источников не редактируются пользователем и не добавляются кнопкой как будто новый адаптер уже существует. Параметры доступа/пароли/произвольный JSON settings в sources не добавляются.

## Сохранение и применение

- В БД сохраняется только уже принятый enabled. Фильтры формы действуют один запуск; постоянного «Сохранить настройки» и скрытых профилей нет. Для следующего запуска ввод выбирается снова. Изменяемая долговременная география источника не хранится в файле вместо БД.
- Вход runner содержит проверенные значения выбора формы; адаптер получает соответствующую ему часть области. Пользователь не вводит произвольный shell-код, URL или пути селекторов. Способ передачи параметров и служебное состояние процесса остаются механизмами предусмотренного runner, не новой доменной таблицей.
- Перед стартом сервер проверяет существование регионов/категорий/сделок, непустой выбор и то, что выбранные источники включены и поддержаны. Неподдержанное сочетание не игнорируется и не подменяется другим: запуск не начинается, форма показывает, что исправить. Это правило валидации, не заявление о уже проверенной поддержке всех маршрутов/сочетаний.
- На старте фиксируется один снимок настроек. Он виден в состоянии и записывается в уже предусмотренный журнал collection с запуском/итогом. Настройки в журнале — основание понять область конкретного запуска, не постоянный профиль и не новые columns/runs-таблицы.
- Переключение enabled во время работы действует на последующие запуски. Для остановки текущего используется уже предусмотренная «Остановить»; фильтры работающего обхода не переписываются.
- Выключение источника и смена области не выключают его ads и не удаляют данные. Снятие публикации подтверждается отдельно по принятому контракту. Объявления вне выбранной области не получают новую метку наблюдения и не считаются снятыми.

## Пример

На «Источниках» включены Циан и Домклик. На «Сборе данных» выбраны обе площадки, Самарская область, новостройки, продажа. Запускается обход только этой области с принятыми30секундами/одним повтором; область фиксируется в журнале. В следующем запуске можно выбрать только Циан, комнаты, месячную аренду — при наличии поддержанного маршрута. Это иллюстрация настройки, не новая живая проверка маршрута.

## Граница решения

Функции запуска/остановки/журнала сохраняются; 4.3не переоткрывается. Редактируемые администратором параметры описаны выше явно, вместо неопределённого «прочие настройки». Если владелец хочет изменяемые таймауты/повторы или постоянные профили, это отдельное новое изменение, не условие выполнения текущего предложения.

Этот вариант принят владельцем17ноября2026. Основание: «Ок, принимаю этот вариант параметров, зафиксируй». Отзывы прежнего и нового критика сохранены отдельно; принятие основано на ответе владельца. Проверка документов не является проверкой интерфейса или runner.
