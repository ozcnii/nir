# Пункт 9 — вывод Docker и повторный запуск сбора

## Вывод работы

Оператор получает вывод команды Django в терминале, где выполняется `docker compose run --rm app python -m app.manage collect URL`. Вывод работающих постоянных сервисов доступен через `docker compose logs -f`. Для существующего контейнера можно прочитать его вывод командой `docker logs <ID контейнера>`. При `--rm` контейнер удаляется после завершения. Если результат нужно приложить к протоколу проверки, вывод команды сохраняют во время запуска.

В рабочем срезе команда печатает результат приёма карточки в JSON с полями `outcome`, `ad_id`, `property_id` и `price_changed`. При штатном завершении по запросу остановки команда выводит `Collection stopped.`. Ошибка команды передаёт причину и ненулевой код завершения. При проверке учитываются вывод команды, состояние контейнера и, для предметных изменений, сохранённые данные.

Для полного обхода вывод отражает область и источник, этап, ключ публикации при наличии, результат, причины пропусков и ошибок, итоговые счётчики. Частичный обход обозначается как неполный. Счётчики обработанных карточек не характеризуют точность сопоставления и покрытие рынка.

## Повторный запуск

Сайт и PostgreSQL запускаются через Compose с тем же томом `db`. Сбор оператор запускает вручную. Полный обход начинает выбранную область сначала. Повторная обработка публикации сохраняет её связь с объектом по ключу `(source_code, external_id)`. История пополняется только при изменении пары `(price_rub, price_kind)`. Уже зафиксированные данные сохраняются при ошибке или прерывании команды.
