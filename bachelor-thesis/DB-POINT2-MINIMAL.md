# Пункт 2 — минимальная схема на согласование

Статус: предложено, не принято. Реализация/миграции отсутствуют. Этот документ заменяет прежние предложения схемы как текущий вариант обсуждения, не изменяя принятые решения автоматически.

## Решение
Пять собственных таблиц: sources, regions, property_types, publications, price_history. Штатные Django auth/admin отдельно. Характеристики хранятся только у publications; кэш общей карточки и отдельная таблица объекта отсутствуют. Одну недвижимость представляет группа строк publications с одинаковым property_group_id UUID. Это метка группы, не FK в несуществующую таблицу.

sources: code TEXT PK, enabled BOOLEAN, request_timeout_seconds NUMERIC positive. code выбирает один из трёх поддержанных сборщиков; бренд отображается из его регистрации, name/id/settings не нужны. Timeout — конкретный параметр ожидания сети, вместо произвольного JSON; значения ещё не выбраны.
regions: id BIGINT PK, name TEXT UNIQUE.
property_types: id BIGINT PK, name TEXT UNIQUE. Значения соответствуют категориям НИР; независимые от названий ID позволяют менять подпись без изменения связей. Мультиязычные имена БД этим не реализованы, столбцы на каждый язык не предлагаются.

publications: id BIGINT PK; property_group_id UUID; source_code FK sources.code; external_id TEXT; url TEXT; region_id FK regions.id nullable; property_type_id FK property_types.id; address TEXT nullable; latitude/longitude NUMERIC nullable pair; area_m2 NUMERIC positive nullable; rooms SMALLINT nonnegative nullable; floor SMALLINT nullable (может быть отрицательным); floors_total SMALLINT positive nullable; deal_type sale/rent_month/rent_day; price_amount NUMERIC(18,2) nullable nonnegative; price_currency VARCHAR(3) nullable; photos JSONB фиксированного формата [{url,phash,hash_version}]; photos_observed_at TIMESTAMPTZ nullable; observed_at TIMESTAMPTZ; status active/removed. Все не помеченные nullable поля обязательны. UNIQUE(source_code, external_id). Неизвестное значение NULL, не ноль. Для студии rooms=0.

price_history: id BIGINT PK; publication_id FK publications.id; observed_at TIMESTAMPTZ; deal_type TEXT; amount NUMERIC(18,2) nullable; currency VARCHAR(3) nullable. UNIQUE(publication_id, observed_at). Период суммы задаётся deal_type, отдельной колонки периода нет. Записываются первая цена и последующие изменения набора deal_type/amount/currency, включая явно неизвестную цену. Прошлые строки неизменяемы. Родительские записи с данными/историей защищены от удаления; source выключается, publication получает статус. FK/уникальные ключи и индекс (publication_id,observed_at) для истории; индекс publications.property_group_id для карточки группы. Не вводить индекс JSON без используемого запроса.

## Группа и карточка
Новая публикация получает существующую группу только при уверенном сопоставлении, иначе новый UUID. При появлении новых фактов/фото сопоставление повторяется, существующие группы могут объединяться: их участники переводятся в выбранный один UUID в короткой транзакции. Нет корневой публикации, self-FK и цепей. Один последовательный исполнитель меняет группировки; перед записью проверяется актуальность. Если появятся параллельные писатели, блокировка группировки проектируется отдельно.
Карточка открывается по стабильному publications.id, затем выбирает строки его текущей группы. UUID группы не обещается постоянной публичной ссылкой. При объединении стабильные ссылки публикаций сохраняют доступ к актуальной группе.
Поиск применяет все фильтры к одной publication, затем выдаёт каждую группу один раз. Нельзя смешивать цену одного объявления и площадь другого. Согласованные и различающиеся значения показываются с источниками, без выбора первой площадки как истины. Физические характеристики не копируются в другую таблицу.

## Контракт collection → catalog
Внутренний вызов accept_publication, не новый HTTP-сервис. Input: source_code, external_id, url, observed_at; region_id, property_type_id; address, latitude, longitude, area_m2, rooms, floor, floors_total; deal_type, price_amount, price_currency; photos known(items)/unavailable. IDs справочников разрешает collection через доступные данные catalog; неизвестный FK отклоняется, новые строки справочников самопроизвольно не создаются. property_group_id и внутренний publication.id вычисляет catalog, сборщик их не назначает.

Каждый ключ контракта присутствует. Неизвестные необязательные значения явно NULL. Если обязательный идентификатор/тип/число не удалось извлечь или нормализовать, collection пишет ошибку и не подменяет это значением NULL в обновлении. Валидатор catalog проверяет типы, единицы/ограничения, пары полей и справочники, не дублирует нормализацию. Повреждённая цена не затирает прежние сведения: пакет отклоняется с причиной. Цена и валюта либо известны вместе, либо обе NULL. Для продажи сумма за объект, rent_month за месяц, rent_day за сутки. Конвертации валют нет.

Фотографии: known(items) заменяет весь список; known([]) очищает; unavailable сохраняет список и photos_observed_at, не блокирует корректную цену. Для known photos_observed_at=observed_at. Неудачная загрузка отдельного фото даёт null для phash/hash_version; старый хеш не объявляется новым. Каталог не обращается в сеть. Совместимость алгоритмов задаёт hash_version. Старые сохранённые признаки не считаются подтверждёнными текущим наблюдением. SHA256 и постоянных файлов нет. Польза pHash на межплощадочных парах ещё не подтверждена, он не единственное основание объединения.

Устаревшее observed_at не применяется. Равное время и равные применимые значения — повтор без изменений; равное время и противоречивое содержимое — conflict без записи. При любом новом принятом наблюдении observed_at продвигается, включая прежнюю цену; поэтому промежуточное запоздавшее сообщение не откатывает данные. Проверка времени/обновление/история/объединение атомарны. Точное воспроизведение старого ответа не требуется, Acceptance отсутствует.
Результат: result created/updated/unchanged/stale/conflict/rejected, publication_id, property_group_id, price_changed, errors с полем/причиной. Подтверждённое снятие: отдельный mark_removed(source_code, external_id, observed_at); прежние характеристики/цена не стираются, цена не добавляется в историю. Обычная сетевая ошибка не снятие. Для неизвестного ключа not_found без создания неполного объявления; отдельного tombstone нет.

## Администрирование и изменения прежних решений
Журнал — файл с просмотром в админке; таблицы логов и запусков не требуются самому хранению объявлений. Учет/управление одним процессом collection.runner и стандартная Django auth сохраняют требуемые функции; конкретная реализация запуска/остановки относится к эксплуатации. Удаление collection Run/Log моделей является предложенным пересмотром физической детализации A10, не отказом от администрирования и не уже принятым изменением.
Физический A4 пересматривается явно: отдельность объекта выражена группой, условия сделки находятся в publication. Это техническое предложение пользователя ещё не принято. Название источника/справочников не означает автоматически поддержку перевода динамических значений.

## Независимая проверка
Новый minimal_schema_sanity_check, fork_turns=none, проверил пяти-табличное основание по первичному НИР5.1–5.5. Признал UUID-метку группы допустимой; отдельная объектная таблица не обязательна. Отметил необходимость явных known/unavailable фото, NULL-перехода цены, атомарности, стабильных карточек по publication.id и сохранения административных функций. Эти условия отражены выше. Проверка проектная, без кода и испытаний источников; новый числовой балл не присваивался.

Обновление после замечаний владельца: хранение request_timeout_seconds в sources отклонено; технический тайм-аут относится к конфигурации приложения. Остальные спорные имена, группировка, валютная политика и JSON-фото остаются на обсуждении. Схема не принята.
