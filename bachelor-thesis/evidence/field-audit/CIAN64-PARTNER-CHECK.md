# Циан 6.4: первичная проверка партнёрских карточек

17 ноября 2026. Исследование публичного HTML, без изменения приложения и без принятия продуктовых решений. Предварительно прочитаны `ROUTES64-PRIMARY-RESEARCH.md` и корневой `ROUTE-COVERAGE-6.4-PROPOSAL.md`. Проверка не закрывает 6.4.

## Метод и первичные адреса

Открыты реально обнаруженные ранее в [областной выдаче комнат посуточно Циан](https://samara.cian.ru/snyat-komnatu-posutochno-samarskaya-oblast/) ссылки:

- [cian.sutochno.ru/detail/1906598](https://cian.sutochno.ru/detail/1906598);
- [cian.sutochno.ru/detail/1157449](https://cian.sutochno.ru/detail/1157449).

Каждая карточка прочитана прямым публичным GET через curl, затем отдельным GET стандартного Python urllib: оба раза HTTP200, конечный адрес совпал с исходным без query. Из HTML извлечён `script#__NUXT_DATA__[type="application/json"]`; это индексированная сериализация Nuxt, поэтому числовые значения ссылок развёрнуты через общий массив. В его корневом `data` присутствуют ключи `detail:1906598` / `detail:1157449`; дополнительно изучены `vuex.detail` и `vuex.search` после снятия обёртки `Reactive`. Индексы массива не являются именами полей и контрактом. Отдельно прочитаны JSON-LD `Product` и `BreadcrumbList`. Контакты, отзывы, полные описания, cookies и служебные параметры сюда не перенесены. Пользовательский браузер не использовался. Для дополнительной проверки основного Циан позднее запущен один собственный изолированный headless Chromium через Playwright с SOCKS5; он закрыт в `finally`, получено подтверждение `CLOSED_OWN_BROWSER`.

## Цена и состояние без дат

| Встроенный путь | 1906598 | 1157449 |
|---|---|---|
| `vuex.detail.objectBasePrice.object_id` | 1906598 | 1157449 |
| `vuex.detail.objectBasePrice.base_price.price` | 9000 | 5800 |
| Там же `currency_id / currency_code` | `1 / RUB` | `1 / RUB` |
| Там же `included_persons` | 2 | 2 |
| Там же `price_per_person` | 2000 | 0 |
| JSON-LD `Product.offers.@type` | AggregateOffer | AggregateOffer |
| JSON-LD `Product.offers.lowPrice / priceCurrency` | `9000 / RUB` | `5800 / RUB` |

В JSON-LD `Product.description` для каждой конкретной карточки явно опубликована единица: соответственно «Цена 9000 RUB за сутки» и «Цена 5800 RUB за сутки». Это первичное подтверждение суточного смысла опубликованной базовой суммы, отсутствовавшее при чтении одного названия `objectBasePrice` или `lowPrice`. Оно не доказывает тариф для любой даты/состава гостей, окончательную стоимость проживания или видимую подпись «от».

В обеих карточках `vuex.search.checkIn=null`, `checkOut=null`, `guests.adults=2`, `guests.childrens=[]`, `guests.pets.value=false`; даты в URL не передавались. `vuex.detail.objectPrice=null`, `hotelPrice=null`, `isSetObjectPrice=false`, `priceObject={}`. В серверном тексте раздел доступных номеров предлагает «Выберите даты», рядом «2 взрослых», «без детей»; конкретная суточная сумма в этом извлечённом тексте не обнаружена. Поэтому здесь подтверждены опубликованные базовые суммы и их суточная единица в метаданных, но не готовый расчёт бронирования в живом интерфейсе. `price_per_person` записан как реальное поле; универсальные правила его применения к цене не испытывались. Публикуемый базовый суточный тариф подтверждён. Наличие included_persons=2 само по себе не делает цену непригодной по P3. Перенос именно этого тарифа в listed/from ещё не согласован: исследователь не выдаёт отсутствие даты/видимой суммы за запрет использования метаданных. До согласования правила образец контракта с этой ценой не утверждён; называть это уже принятым правилом unavailable было бы ошибкой.

## ID и граница пространства ключей

У обеих публикаций один и тот же ID одновременно присутствует в фактическом `/detail/<ID>`, `data['detail:<ID>'].id`, встроенном `url` на `sutochno.ru/front/searchapp/detail/<ID>` и `objectBasePrice.object_id`. Повторный независимый GET сохранил эти ID и `type`. Это подтверждает воспроизводимый ключ конкретной публикации данного партнёрского семейства на момент проверки. Даты, гости и рекламные параметры частью этого наблюдаемого ключа не являются.

Данные прямо связывают эти ключи с объектами Суточно.ру; они не устанавливают, что число является ID основного Циан `/rent/flat/<ID>/`. В частности, отсутствие коллизий числовых ID между основным Циан и партнёром, между разными партнёрскими хостами или после снятия/перепубликации не доказано. Совпадение структуры с ранее проверенным domclick.sutochno.ru не доказывает совместность пространств ключей. Формат `external_id`, новый источник или правило слияния здесь не выбираются. Для полного утверждения о коллизиях одной пары примеров недостаточно.

## Пустая выдача и ограничения

Свежий GET исходной областной выдачи Циан дал HTTP200, но только около 2,2 КБ HTML со spinner и служебным защитным JavaScript вместо списка и фильтров. Отдельный запрос этого же опубликованного URL через разрешённый SOCKS5 `127.0.0.1:10808` дал такое же ограниченное содержимое. Это ограничение доступа текущего исполнителя, а не пустая выдача. После этого выполнена одна браузерная проба этого опубликованного адреса в собственном Chromium. Страница перешла на служебный путь `/xpvnsulc/` и показала готовый текст проверки человека с просьбой развернуть картинку. H1 и ссылки выдачи отсутствовали. Защита не проходилась, повторных попыток не было.

В том же собственном браузере один раз открыт ранее реально опубликованный [адрес группы multi_id=330631068](https://samara.cian.ru/cat.php?deal_type=sale&engine_version=2&multi_id=330631068&offer_type=flat&region=4966&room3=1). После ожидания получена та же явная проверка человека, без H1 и списка объявлений. Поэтому состав группы, её география и завершённость не уточнены относительно прежнего первичного наблюдения. Браузер закрыт после этих двух переходов; сессионные URL проверки и их параметры здесь не сохраняются.

Из таких ответов нельзя получить новые подтверждённые фильтры для явно пустого запроса. Выдуманные query, границы цены и номера страниц не создавались. **Явная пустая выдача остаётся непроверенной.** Свежая цепочка выдача → две партнёрские ссылки также не воспроизведена: происхождение ссылок установлено предыдущим первичным исследованием, доступность и данные назначений проверены сейчас. Не проверены живые кнопки, пагинация партнёра, конец выдачи, полная региональная матрица, устойчивость схемы во времени и работа будущего адаптера.

### Дополнительный ограниченный заход к проверке человека

По ранее данному разрешению на прохождение CAPTCHA запущен новый собственный изолированный Chromium с тем же SOCKS5. На исходной опубликованной выдаче показана визуальная проверка поворота изображения. Изображение просмотрено на снимке экрана, ползунок перемещён мышью до визуально вертикального положения; выполнено одно отпускание ползунка. После ожидания сайт снова показал страницу проверки человека с новым заданием, H1 и выдача не появились. Успешное прохождение не подтверждено. Новое задание не решалось, дальнейших попыток не было; Chromium закрыт, получено `CLOSED_OWN_BROWSER`. Поэтому новых доказательств для группы, кнопки «Дальше» и штатного пустого фильтра этот заход не дал. Снимки и служебные параметры проверки в проект не добавлялись.

### Граница нормализации гостиничного номера

Название типа «отдельные комнаты, номера» охватывает и гостиничные номера. Публикация1906598 — четырёхместный номер с внутренним rooms2; это не доказательство набора двух самостоятельно сдаваемых комнат по6.2. Автоматический перенос rooms2 в число сдаваемых комнат не утверждён. Для принятогоконтракта остаётся явно определить обработку таких номеров, не меняя молча смысл rooms.
