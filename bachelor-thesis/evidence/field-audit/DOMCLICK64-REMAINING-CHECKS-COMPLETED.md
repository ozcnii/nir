## 2. Восстановление доступа

Для api.ipify.org выход физически привязанного curl en0 совпал с SOCKS10808, выход существующего SSH SOCKS1080 отличается (сохранены только SHA256): dom64-recovery-egress.json. Это контроль конкретного endpoint, не доказательство маршрута всех доменов. Через1080 собственный Chromium дал HTTP401 и готовую страницу403: dom64-recovery-ssh-proxy.json.

В registry собственных Playwright MCP найден исторический профиль workspace ssau/7sem; личный Chrome не открывался. Для проверки использована временная копия этого исследовательского профиля, Chrome с прежними опубликованными в registry launchargs, SOCKS10808. Получена полноценная главная после начального401; далее карточки/выдачи HTTP200: dom64-recovery-own-prior-profile.json. Сам факт успеха этой комбинации не доказывает, что причиной прошлых403 был исключительно IP, профиль или один launcharg. Системные VPN/маршруты и исходный профиль не менялись. Свои браузеры закрыты, временная копия профиля удалена.

Правило штатного4.3 о завершении источника на ready401/403/429 сохраняется. Данные действия — отдельно запрошенное исследование восстановления доступа, не retry реализации сборщика.
