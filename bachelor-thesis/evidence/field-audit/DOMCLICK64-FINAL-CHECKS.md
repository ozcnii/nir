## Как понимать результат

Обычный видимый клик «Фильтры» без дат открывает календарь; исследовательское применение реально существующей формы программно не объявляется обычным видимым пользовательским потоком. Оно проверяет собственный обработчик и фактический ответ источника без произвольного подбора дат/APIquery. Самостоятельный вызов этих внутренних поисковых API сборщиком не согласован и здесь не вводится.

Пустой успешный ответ категории подтверждает пустоту данного контекста сейчас, а не отсутствие домов/комнат вообще и не неподдержку фильтра. Положительные допустимые house/room не получены; шале/барн с categoryflat не переименованы в house наугад. Согласованный гостиничный отсев сохраняется.

Pager использует несовместимые счетчики20/36 и продолжает публиковать ссылки после последнего непустого окна. Числа24/40 нельзя считать числом рабочих страниц. По принятому4.3 повтор навигационного состояния останавливает этот обход как неполный/с ошибкой, не как успешный полный сбор. Повтор UUID сам по себе не критерий остановки. На Циан URL также может не меняться при реальном продолжении; состояние должно включать фактическую страницу/контекст, не один URL. Это применение принятого4.3, не новая продуктовая настройка.

Для повторной загрузки generic /search нужно сохранить подтвержденную географию исходного задания и проверить фактическое состояние; голая ссылка?page не доказывает ее сохранение. Новые таблицы/поля/продуктовые решения не вводились. Полный областной последовательный обход22страниц не выполнялся; переходы2/22/23 и реальный цикл проверены.

## Граница сохраненного протокола HTTP

В четырех файлах house/room сохранены итоговыеquery/total/count, но HTTPstatus/fetchStatus отдельнымиполями не записаны. Для dom64-final-region-room.json фактическое инструментально выполненное ожидание было `page.waitForResponse(r=>r.url().includes('/api/offers/ad/v1') && r.status()===200)` до чтения response.json(); это подтверждение исполнителя по выполненному действию, а не сохраненный в JSON заголовок. В остальных трех файлах независимому читателю доступны query и нули, но статус нельзя восстановить из этихJSONсамих. Готовая UIпустота/SSRsuccess после SPA не заявляется: фиксируется нулевой серверный результат после обработкиформы. Для независимого воспроизведения именно транспортногостатуса трех остальных проб требуется дополнительный capture; успешная проба областиroom не повторялась радидублирования.

Отказы основногоДомклик описывают разные разовые исследовательскиеметоды по запросу владельца, а не автоматические retry в одном рабочемrun. Принятый4.3 для будущего сборщика сохраняется: готовый401/403/429 завершает источник. Эти исследовательские контексты не доказывают реализацию4.3.
