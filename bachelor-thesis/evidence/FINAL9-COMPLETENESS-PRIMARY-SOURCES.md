## Минимальный web-запуск — новое предложение, не принятие

Поиск runserver/DEBUG/ALLOWED_HOSTS/SECRET_KEY/staticfiles/--noreload по Markdown комплекта, включая DECISIONS и принятые container/runtime/first-launch документы, не выявил принятия **полного профиля** ниже. Уже принято: сервер внутри app слушает0.0.0.0:8000, host публикуется только на127.0.0.1 с автоматическим свободным портом при конфликте. Сводка допускает локальный runserver; это не отдельное принятие команды/настроек.

Кандидат: `python manage.py runserver 0.0.0.0:8000 --noreload --insecure`, `DEBUG=False`, штатные `django.contrib.staticfiles`/`STATIC_URL`, `ALLOWED_HOSTS=['127.0.0.1','localhost']`; уникальный стабильный SECRET_KEY однократно в игнорируемом локальном env, без включения в Git/image и без пересоздания при каждом запуске. Настройки/файлы сейчас не создавались.

Первичные основания Django5.2: [runserver/--noreload](https://docs.djangoproject.com/en/5.2/ref/django-admin/#runserver) — сервер разработки и отключение autoreload; [staticfiles](https://docs.djangoproject.com/en/5.2/howto/static-files/#serving-static-files-during-development) — автораздача при DEBUG; [ALLOWED_HOSTS](https://docs.djangoproject.com/en/5.2/ref/settings/#allowed-hosts) — имена без портов, поэтому переменный host-порт список не меняет; [SECRET_KEY](https://docs.djangoproject.com/en/5.2/ref/settings/#secret-key) и [checklist](https://docs.djangoproject.com/en/5.2/howto/deployment/checklist/#secret-key) — уникальный секрет вне исходников, его смена инвалидирует подписанные данные/сессии. Игнорируемый env и отказ от автосброса — проектный способ выполнения, не требование Django о конкретном имени файла. Local-only обеспечивается host-loopback публикацией, а не0.0.0.0 внутри контейнера. Это не production и не его конфигурация; реальный запуск/admin/CSS/авторизация/перезапуск ещё не проверены.

## Уточнение после независимого ревью: APIошибки и DEBUG

Первоначальный предложенный DEBUG=true конфликтовал с принятым JSON5.5: Django при DEBUGtrue не использует обычные404/500errorviews и показывает техническийответ. Актуальное предложение выбирает DEBUG=false и runserver--noreload--insecure только для loopbackлокального запуска. Staticfilesflag разрешает раздачуCSS/admin при DEBUGfalse; он не предназначен дляproduction и не работает с ManifestStaticFilesStorage, поэтому сохраняется обычный StaticFilesStorage. Дополнительныйserverpackage/новаяошибочнаяAPIсхема не вводятся. [Django5.2 error views](https://docs.djangoproject.com/en/5.2/ref/views/#the-500-server-error-view), [staticfiles --insecure](https://docs.djangoproject.com/en/5.2/ref/contrib/staticfiles/#cmdoption-runserver-insecure).

Прежний абзац о DEBUGtrue выше описывает факт штатной автораздачи, ане текущийвыбранныйпрофиль. Теперь явнаяраздачачерез--insecure приDEBUGfalse сохраняет errorhandlersJSON5.5. РеальныйHTTPтест неизвестного/api/*/непредвиденного500/adminCSS остаётся будущимсценариемF18, не выполненным результатом.
