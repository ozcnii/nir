Дата проверки первичных источников: 18 ноября 2026 года. Статус: исследование для обсуждения, профиль не утверждён. Установка, обновление и запуск контейнеров не выполнялись; работоспособность приложения в контейнерах здесь не проверена.

Выбор целевого комплекта не означает установку или обновление хоста. Точная версия Docker Desktop относится к среде разработчика, а не к образу приложения.

## Платформа и сопровождение

Docker выпускает отдельный Desktop для Apple silicon. Требования Mac: поддерживаемая macOS, не менее 4 GB RAM; Rosetta 2 рекомендуется для отдельных необязательных Darwin/AMD64-инструментов, но не является строгим общим требованием. Политика macOS охватывает текущий и два предыдущих основных выпуска. [Требования Docker Desktop для Mac](https://docs.docker.com/desktop/setup/install/mac-install/#system-requirements).

Apple подтверждает публичный выпуск macOS 27; поэтому переданное основным агентом окружение macOS 27.0.1 ARM64 попадает в текущую основную ветку по политике Docker. Это вывод из политики, а не отдельное обещание Docker о проверке сочетания именно 27.0.1 и Desktop 4.94.0. [Apple security releases](https://support.apple.com/en-us/100100), [Docker Mac requirements](https://docs.docker.com/desktop/setup/install/mac-install/#system-requirements).

Нельзя отождествлять «недавно выпущена» и «получает исправления безопасности». Docker указывает исправления только в последнем Desktop; платная поддержка Pro/Team относится к последней версии, Business также охватывает версии возрастом до шести месяцев. Следовательно, для 4.94.0 нельзя обещать security backports. Это ограничение описания baseline, а не разрешение автоматически обновлять установленное ПО. [Docker support: supported versions](https://docs.docker.com/support/#supported-versions).

Причина целевого выбора: это единый последний опубликованный комплект, соответствующий политике исправлений Docker. Кроме того, в Desktop 4.98.0 после установленного 4.94.0 исправлена ошибка ядра Linux IPv4 TCP, обозначенная CVE-2026-98432. Это конкретное изменение в более новом комплекте; из него не следует, что старый комплект неработоспособен или несовместим с API приложения. [Docker Desktop 4.98.0: Security](https://docs.docker.com/desktop/release-notes/#4980).

## Достаточные возможности Compose

Обычные `services`, `healthcheck` и `depends_on` с `condition: service_healthy` подходят для согласованной схемы «приложение + PostgreSQL». Compose ждёт успешной healthcheck зависимости перед созданием приложения; один только порядок запуска означает лишь запуск процесса, а не готовность БД принимать запросы. Официальный пример использует PostgreSQL и `pg_isready`. Вывод для проекта: экспериментальные jobs, отдельный оркестратор и новый механизм ожидания ради этой схемы не требуются. Проверка готовности не заменяет прикладные миграции и обработку ошибок соединения. [Compose startup order](https://docs.docker.com/compose/how-tos/startup-order/).

Для локального веб-интерфейса следует явно задавать host IP `127.0.0.1` при публикации порта; без адреса Docker публикует порт на всех адресах хоста. Документация оговаривает доступ соседей L2 к localhost-публикациям в Engine старше порога, то есть в версиях ниже 28.0.0; установленный Engine 29.8.2 выше этого порога. Это не результат сетевого испытания данного проекта. [Docker port publishing](https://docs.docker.com/engine/network/port-publishing/), [исходник официальной страницы](https://github.com/docker/docs/blob/main/content/manuals/engine/network/port-publishing.md).

## Нужен ли именно Docker Desktop

Docker Desktop включает Engine, CLI и Compose и является рекомендованным Docker способом установки Compose на Mac. [Docker Compose installation overview](https://docs.docker.com/compose/install/).

Однако требование проекта к Compose не означает обязательность замены уже работающего провайдера на Docker Desktop. OrbStack документирует собственный Docker Engine, CLI и Compose и запуск обычных проектов через `docker compose`. Если обнаружен существующий OrbStack, версии надо получать из его установленного окружения; версии комплекта Desktop ему не приписываются. В текущем случае основной агент обнаружил `desktop-linux`, поэтому миграция на OrbStack не предлагается. [OrbStack Docker containers](https://docs.orbstack.dev/docker/).
