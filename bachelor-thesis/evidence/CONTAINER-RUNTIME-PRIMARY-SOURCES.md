# Пункт 9: первичные источники для runtime app/Chromium

Проверено 18 ноября 2026. Это исследовательская записка для предложения, не принятое решение и не реализация. Принятые python:3.13.18-slim-bookworm, Playwright Python1.65.2, Compose app/db и runner внутри app сохраняются. Код, Dockerfile, Compose и seccomp-конфигурация не создавались; установки, сборки и запуски не выполнялись.

## Подтверждённые факты

| Область | Что установлено по первоисточнику |
|---|---|
| Публикация порта | Docker по умолчанию публикует порт на всех адресах хоста; явный 127.0.0.1 ограничивает опубликованный порт локальным хостом при стандартной bridge/NAT-сети. Это не защита от самого владельца Docker или специально изменённой маршрутизации. [Docker port publishing](https://docs.docker.com/engine/network/port-publishing/). |
| Связь app/db | Compose создаёт общую сеть, сервисы находят друг друга по имени. Соединение между ними использует порт контейнера; публиковать PostgreSQL на хост ради app не требуется. [Compose networking](https://docs.docker.com/compose/how-tos/networking/). |
| Пользователь | Compose может переопределить runtime-пользователя; без USER образа/переопределения это root. Число10001 документацией не предписывается. [Compose user](https://docs.docker.com/reference/compose-file/services/#user). |
| Sandbox API | В исходнике Python именно tag v1.65.2 у launch описан chromium_sandbox, значение по умолчанию false; headless по умолчанию true. Одного non-root недостаточно, чтобы API включил sandbox. [Python1.65.2 generated API](https://raw.githubusercontent.com/microsoft/playwright-python/v1.65.2/playwright/sync_api/_generated.py). |
| Linux sandbox в Docker | Playwright для crawling рекомендует отдельного пользователя и seccomp-профиль. Root отключает Chromium sandbox. Приведённый профиль дополняет Docker-профиль разрешением clone/setns/unshare для создания user namespaces. Это не рекомендация seccomp=unconfined. [Playwright Python Docker](https://playwright.dev/python/docs/docker), [официальный профиль](https://raw.githubusercontent.com/microsoft/playwright/main/utils/docker/seccomp_profile.json). |
| Граница seccomp | Docker seccomp — внешний фильтр системных вызовов контейнера; Chromium sandbox — внутренний механизм браузера. Docker default profile ограничивает создание namespaces; разрешённый syscall сам по себе не гарантирует доступность namespaces в ядре и прочих политиках. [Docker seccomp](https://docs.docker.com/engine/security/seccomp/). |
| Chromium и shell | Обычный headless-запуск без channel использует отдельный chromium-headless-shell. channel="chromium" выбирает полный bundled Chromium с новым headless-режимом; это не Chrome latest. Установка chromium штатным Playwright не равнозначна обязательному выбору полного браузера при launch. [Playwright browsers](https://playwright.dev/python/docs/browsers#chromium-headless-shell). |
| Аргументы запуска | В текущем upstream core chromium.ts добавляет --no-sandbox, если chromiumSandbox не true; выбор shell/full происходит отдельно по channel/headless. Поэтому утверждать, что shell по определению не поддерживает sandbox, оснований нет. Это чтение main, не доказательство реализации driver из Python1.65.2: upstream core URL tag v1.65.2 вернул404. [Core source](https://raw.githubusercontent.com/microsoft/playwright/main/packages/playwright-core/src/server/chromium/chromium.ts). |
| Init и shared memory | Compose init запускает PID1, который передаёт сигналы и подбирает дочерние процессы. shm_size задаёт размер /dev/shm контейнера. [Compose init](https://docs.docker.com/reference/compose-file/services/#init), [Compose shm_size](https://docs.docker.com/reference/compose-file/services/#shm_size). Docker default /dev/shm —64m. [Docker runtime](https://docs.docker.com/engine/containers/run/#runtime-constraints-on-resources). |

Playwright отдельно рекомендует --init против zombie processes и --ipc=host против исчерпания Chromium shared memory. SYS_ADMIN приведён только как локальный диагностический совет при странных ошибках, а не обязательное условие штатного sandbox. [Playwright Docker recommendations](https://playwright.dev/python/docs/docker#recommended-docker-configuration).

Linux user namespaces могут ограничиваться политиками хоста. Chromium отдельно документирует ограничения AppArmor в некоторых Linux-дистрибутивах. Переносить эту проблему автоматически на Docker Desktop Mac нельзя: Linux-контейнер использует ядро Linux VM, а не ядро macOS. Совместимость конкретной VM/Engine и будущего профиля ещё не проверена. [Chromium AppArmor notes](https://chromium.googlesource.com/chromium/src/%2B/main/docs/security/apparmor-userns-restrictions.md).

## Практичное предложение для проекта

Это проектные значения для согласования; источники подтверждают механизмы, но не выбирают параметры за владельца.

- Снаружи app доступен как http://127.0.0.1:8000; отображение host127.0.0.1:8000 → app8000. Внутри app HTTP-сервер слушает0.0.0.0:8000, иначе Docker-публикация не достигнет его через интерфейс контейнера. db доступен app как db:5432; host port для db отсутствует. Под «внутренним портом» здесь понимается отсутствие публикации, не обязательный network internal:true: сборщику нужен исходящий доступ к сайтам.
- App, runner и браузер работают как именованный пользователь app с UID/GID10001:10001. Для него предусмотрены домашняя папка и доступные на запись временные каталоги; код и установленные browser binaries не требуют записи в runtime. Root нужен на этапе сборки для системных пакетов, а не для штатного запуска app.
- В будущем launch явно задаёт headless=True, channel="chromium", chromium_sandbox=True. Выбор полного bundled Chromium делает профиль однозначным; это предложение без смены принятого пакета/браузерной ревизии. Не добавляются --no-sandbox, --disable-setuid-sandbox, privileged, SYS_ADMIN или seccomp=unconfined. Если sandbox не запускается, профиль считается непроверенным/неработающим; автоматическое отключение sandbox не является fallback.
- Для app предлагается init:true, собственный IPC namespace и штатные browser arguments без shm_size, ipc:host и ignore_default_args. Текущий upstream chromiumSwitches.ts содержит --disable-dev-shm-usage; Chromium описывает этот флаг как использование временного каталога для anonymous shared memory files вместо проблемного малого /dev/shm. Поэтому увеличение /dev/shm само по себе не доказывает пользу для выбранного запуска. Нужен доступный UID10001 временный каталог /tmp и свободное место в контейнерном хранилище; жёсткий лимит памяти не подбирается без замеров. Это осознанный стартовый вариант на штатном механизме Playwright, отличающийся от общего Docker-примера ipc:host; достаточность для одного браузера и двух страниц ещё не проверена. [Playwright default switches](https://raw.githubusercontent.com/microsoft/playwright/main/packages/playwright-core/src/server/chromium/chromiumSwitches.ts), [Chromium switch definition](https://chromium.googlesource.com/chromium/src/%2B/lkgr/base/base_switches.h).
- Для namespace sandbox предлагается готовый полный официальный seccomp-профиль Playwright, происходящий от Docker default и дополненный разрешениями clone/setns/unshare. Не предлагается самостоятельно собирать второй профиль из нового Docker default. При реализации фиксируются источник/commit/hash готового файла и проверяется совместимость с выбранным Engine; профиль из main не объявляется автоматически совпадающим с default Engine29.9.3. Наличие файла и соответствующие runtime-права должны быть частью воспроизводимого комплекта, а не ручной настройки компьютера. Сейчас файл не создаётся.

## Будущая сборка без изменения принятой базы

Штатный install --with-deps chromium устанавливает браузер и его Linux-зависимости. Это делается выбранным пакетом1.65.2 в Linux app во время сборки под root. Install без выбранного браузера ставит лишние браузеры; системный apt chromium и независимый Chrome latest здесь не нужны. [Playwright installation](https://playwright.dev/python/docs/browsers#install-system-dependencies).

Обычный Linux browser cache — ~/.cache/ms-playwright: установка под root туда и последующий запуск другим пользователем создают несовпадение пути. Playwright документирует общий PLAYWRIGHT_BROWSERS_PATH при установке и при запуске. Предлагается один постоянный путь /ms-playwright внутри image, одинаковый в обоих этапах, с чтением/исполнением для10001 и всех родительских каталогов. Root-owned binaries не обязаны быть world-writable. [Browser cache](https://playwright.dev/python/docs/browsers#managing-browser-binaries).

Официальный Python Dockerfile v1.65.2 подтверждает приём build-time browser/deps install и /ms-playwright; в нём используется Ubuntu noble и системный Python. Поэтому он служит примером механизма, но не заменой принятого python:3.13.18-slim-bookworm и не гарантией точной версии Python проекта. Его chmod777 не требуется механически переносить в образ с одним известным runtime UID. [Python1.65.2 Dockerfile](https://raw.githubusercontent.com/microsoft/playwright-python/v1.65.2/utils/docker/Dockerfile.noble).

При разрешённой реализации нужны проверка фактического UID, доступности browser/cache/temp, запуска именно полного Chromium с включённым sandbox на обеих целевых архитектурах и целевого сценария сбора, корректного завершения дочерних процессов. До этого достаточность temporary storage, доступность user namespaces и работоспособность собранного образа не считаются экспериментально подтверждёнными. Если будет подтверждён риск shared memory/I/O, отдельно сравнивается private shm_size с удалением только --disable-dev-shm-usage через список ignore_default_args; массовое отключение default arguments не предлагается.
