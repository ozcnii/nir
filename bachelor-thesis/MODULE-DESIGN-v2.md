# Уточнение трёх модулей — предложение v2

**Обновление статуса:** пользователь принял A7 — фото без постоянного хранения, обработка в памяти, показ по ссылке. Старые предложения обязательного фотоархива не действуют. Остальные новые детали остаются предложениями.

Статус: НЕ ПРИНЯТО. Реализация отсутствует. A1–A6 не изменяются. Этот документ уточняет неоднозначности старого D1–D4 и предлагает альтернативу постоянному хранению фото. Шесть архитектурных направлений не означают принятия этих деталей.

## Владение и зависимости

- collection владеет источниками, заданиями, исходными запросами и полученными ответами/контрольными точками; разбирает специфичные поля площадки. Не меняет объекты и их группы.
- catalog владеет публикациями, сохранёнными исходными наблюдениями, общей нормализацией, сделками/ценами, объектами, членством публикаций и ручными ограничениями. Это единственный модуль, применяющий объединение/разделение. Внутри раздельны приём, нормализация, применение членства и представления страниц.
- matching владеет производными признаками/результатами экспериментов и объяснениями. Читает зафиксированные входные версии, возвращает предложение. Исходные сведения, цены и членство не переписывает.
- Явный сценарий в точке запуска связывает вызовы; нет цепочки save-сигналов. Протоколы обмена передают данные/версии/ошибки; collection не импортирует обработчики каталога, catalog не запускает matching сам. Сценарий не является четвёртой предметной подсистемой.

## Один проход и сбои

1. Задание получения карточки имеет идентификатор операции. Успешный ответ сохраняется collection с URL, временем, версией парсера и контрольной суммой. В одной транзакции базы фиксируется полученный результат и следующий этап. При сбое после HTTP до фиксации запрос может повториться; не заявляется exactly-once доставка.
2. catalog принимает полученный результат с тем же идентификатором. Уникальный ключ приёма не даёт повторно создать одно наблюдение. Сохранение исходных сведений предшествует нормализации. Следующий отдельный проход создаёт новое наблюдение даже при прежней цене.
3. Нормализация создаёт версию результата, а ошибка остаётся рядом с исходными сведениями; последняя успешная версия публикации не затирается. Вход повторной обработки — сохранённые сведения, а не обязательная новая загрузка страницы.
4. matching рассчитывает предложение на конкретных версиях нормализации и состояния групп/ручных ограничений. Результат расчёта не означает применения.
5. Для первого варианта предлагается одна строка версии состояния групп. И автоматическое применение, и ручная правка блокируют её через штатный select_for_update в короткой транзакции. Проверяют ожидаемую версию и версии входных наблюдений, ручные ограничения; устаревший расчёт отклоняют. Успешное изменение, запись истории и увеличение версии происходят совместно. Этот простой вариант сериализует изменения групп; масштабирование блокировок потребует отдельного решения. Все операции смены нормализованной версии, влияющие на совпадение, должны участвовать в том же протоколе проверки, иначе остаётся гонка.
6. Смена состояния этапа и создание следующего задания фиксируются одной транзакцией PostgreSQL. Перезапуск ищет незавершённые этапы. Сетевые операции и расчёт признаков выполняются вне транзакций. Идемпотентность обеспечивается ключом операции/этапа/версии, а не обещанием однократного выполнения. Механизм восстановления исполнителя — отдельная не принятая деталь; старая идея собственного worker также не считается автоматически утверждённой.

## Фото: два различных действия

Постоянное сохранение исходных фото не принято и не следует автоматически из сравнения фото. Для вычисления pHash нужно получить и декодировать байты изображения; постоянный файл не обязателен.

Предложение для обычного режима: хранить исходный URL, источник/наблюдение/позицию, время проверки, состояние доступности, контрольную сумму полученных байтов и рассчитанный признак с версией алгоритма. Обрабатывать изображение в памяти без постоянного файла. Показывать внешний URL с запасной ссылкой на объявление при ошибке. Видео и прочие медиа не собирать без отдельной задачи — они не нужны принятому сравнению фото.

Новая версия фото по прежнему URL возможна: checksum связывает признак с конкретно полученным содержимым, URL сам по себе не идентификатор версии. Фотография может стать недоступной: это состояние фото, не снятие публикации. Повтор при сбое не удаляет старый признак. Ограничения размера/времени/декодирования и обращения только к ожидаемым публичным хостам нужны при реализации загрузки; точные значения ещё не приняты.

Последствия: нет гарантии будущего показа фото; нельзя заново вычислить другой алгоритм по исчезнувшему оригиналу. Для полностью воспроизводимого фотоэксперимента выбор отдельного исследовательского набора/архива обсуждается отдельно, а не превращается в обязательный архив всех объявлений.
