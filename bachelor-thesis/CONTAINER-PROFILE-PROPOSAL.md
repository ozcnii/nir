# Пункт 9 — контейнерный профиль app и Docker/Compose

**ПРИНЯТО.** 18 ноября 2026. Владелец прямо принял контейнерный профиль. Уже приняты только Compose app/db, runner внутри app, volume db и исключение обязательного backup/restore; версии приложения из 8.5 сохраняются. Этот документ предлагает точный base image и целевой Docker-комплект. Dockerfile/compose.yaml/код/конфигурации не создаются, обновления/установки и запуск контейнеров не выполняются.

## 2. Совместимость и сборка

- Сохраняем точный Python3.13.18, Django5.2.19, uv0.13.9, PlaywrightPython1.65.2 и остальные версии 8.5. Не устанавливаем второй Python из Debian поверх выбранного interpreter и не подменяем его автоматически последним.
- Во время будущей сборки устанавливаются Chromium и системные библиотеки именно выбранным Playwright; база Python сама их не содержит. Браузер/зависимости находятся внутри Linux app. Host .venv и браузер с macOS в image не копируются.
- На Mac используется Linux arm64, на x86-64 машине — Linux amd64. Общий manifest/index закрепляет обе платформы; не заставляем Mac выполнять amd64 ради совпадения названия image. Код/lock/версия base общие, бинарные слои платформ различаются.
- Debian12 в app и Ubuntu24.04 hosted CI — две поддерживаемые среды, а не одинаковая ОС. Принятые CI-процедуры 8.4 не заменяются новым Compose workflow. Этот профиль относится к локальному приложению; он не требует устанавливать Docker Desktop на GitHub-hosted Linux.
- Итоговый image app получит собственный digest только после реальной сборки. Base digest не выдаётся за фиксацию всех apt-пакетов, browser assets и артефактов приложения. При разрешённой сборке сохраняются реальный image digest и версии; обновления проходят согласованно по 8.5.

## 3. Что реально установлено сейчас

Главный агент выполнил только read-only команды: docker --version, docker compose version --short, docker context show, docker version с полями Client/Server и чтение Info.plist Docker.app. Получено:

- Docker Desktop4.94.0;
- Docker Client/Engine29.8.2;
- Compose5.5.1;
- context desktop-linux, daemon уже работал.

Это имеющийся baseline, отличающийся от принятого, но ещё не установленного целевого профиля 4.99.0 и не свидетельство проверки приложения. Ничего не запускалось/не останавливалось/не обновлялось. Существующая связка не объявляется неработоспособной: её можно отдельно выбрать вместо целевого обновления, но такое изменение нельзя принимать за владельца. Принятие профиля и разрешение реально обновлять используемый другими задачами Desktop — разные действия.

Актуальная политика Docker предусматривает исправления в последних выпусках; 4.98 после установленной4.94 содержит исправление kernel IPv4 TCP. Поэтому предлагается текущий единый комплект, а не бессрочная фиксация имеющегося хоста. Это обоснование выбора, не утверждение о доказанной эксплуатации уязвимости на компьютере. Подробные факты/ссылки: [CONTAINER-PROFILE-DOCKER-SOURCES.md](evidence/CONTAINER-PROFILE-DOCKER-SOURCES.md).

## 4. Что этот выбор закрывает и чего не закрывает

Владелец принял base app, платформы и точные локальные версии Desktop/Engine/Compose. В сводке 9 этот выбор зафиксирован как принятый. Сам профиль не запускает Docker, не меняет хост и не закрывает весь пункт9.

Остаются отдельно: параметры запуска/порты/пользователь и browser sandbox/init/shm; первоначальные миграции/служебная и runtime-роль; хранение журнала/служебного состояния при restart и владение/очистка ресурсов; полный сводный проект/реестр схем и документов. Это уже перечисленные области9.4, не новые функции продукта. Не добавляются очередь, третий постоянный сервис или backup. Обязательные P6/F25 и правила8.3/8.4 сохраняются.

Для будущего подтверждения при реализации: прочитать фактические версии в собранном app, проверить Chromium под выбранным runtime-пользователем, старт app после готовности db/миграций, каталог/JSON и сохранность volume. До этого профиль считается выбранным по опубликованным требованиям и артефактам, не испытанным контейнерным окружением.

Доказательства base image: [CONTAINER-PROFILE-APP-SOURCES.md](evidence/CONTAINER-PROFILE-APP-SOURCES.md). Профиль принят владельцем 18 ноября 2026. Отзыв нового чистого критика сохраняется отдельно; оценка не заменяет решения владельца.
