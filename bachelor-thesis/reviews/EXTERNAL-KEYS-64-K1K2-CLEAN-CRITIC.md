# Независимая проверка правила внешних ключей 6.4 — K1/K2

Проверен проект `EXTERNAL-KEYS-6.4-PROPOSAL.md` и только четыре указанных в нём первичных материала: `CIAN64-PARTNER-CHECK.md`, `DOMCLICK64-BROWSER-CHECK.md`, `domclick64-card-fields.json`, `embedded-card-matrix-2026-11-17.json`. Другие отзывы, решения, планы и история не использовались. Сетевые запросы и проверки приложения не выполнялись; код не изменялся.

**Готовность спецификации к согласованию: 9,5/10. Обязательных замечаний к правилу не найдено.** Это оценка определённости предложенного правила и его соответствия сохранённым данным, а не готовности реализации. Согласование остаётся за владельцем.

## Проверка правила

| Проверяемая граница | Результат |
|---|---|
| Семейство и источник | Семейства различаются до извлечения ключа. `cian` и `domclick` сохраняются; отдельный формат не превращается в новый источник. Числовой основной Циан и `/detail/<ID>` конструктивно различаются. У Домклик `/detail/<ID>`, `/card/sale__…` и `/card/<UUID>` также различаются. |
| Hostname и полный путь | У новых семейств заданы точные hostname, полный путь, положительный десятичный ID без ведущих нулей либо UUID установленной формы. Лишние сегменты, dot-сегменты, обратные слеши и кодирование идентификатора не разрешены. `24.domclick.ru` явно исключён из автоматического признания региональным основным сайтом. |
| Канонизация и повтор | Единственный завершающий slash удаляется, регистр UUID нормализуется, query и fragment не участвуют в ключе. Изменение этих частей не создаёт новую публикацию. Протокол и допустимый порт ограничены отдельно. Принятые native-ключи не переводятся в новые форматы. |
| Публичный и встроенный партнёрский URL | Реальный Циан `/detail/1906598` и встроенный `https://sutochno.ru/front/searchapp/detail/1906598` правильно различены. Второй адрес подтверждает ID, но не создаёт ключ `/front/searchapp/detail/1906598` и не меняет `source_code`. В данных так же согласован второй ID `1157449`. |
| Домклик24 | Для реального `1999c326-4f66-410d-8ea7-0d01a6e8af4e` используется `inventory.searchData.id`, а не отличный `inventory.data.uid=0f993e54-dbfc-4633-bf0a-4224738136b3`. Второй пример `98497d9e-fe9c-44b1-8ec5-902e6d27763b` подтверждает то же различие. Указание читать inline SSR учитывает исчезновение глобального свойства после гидратации. |
| Переходы и несовпадение | Согласуются вход, конечный публичный URL и встроенный ID активной карточки. Реально наблюдавшееся добавление `?adt=1` не меняет ключ. Другой ID/семейство, расхождение либо невозможность подтверждения дают `unavailable` известного входа; данные назначения не подменяют исходную публикацию. |
| Неправильный вход | Без корректно определённого входного ключа конверт не создаётся, заглушки не используются; для невалидного конверта сохранён `rejected`. Поэтому ошибка распознавания не создаёт искусственную идентичность. |
| Антибот и снятие | CAPTCHA, выдача, главная и общий 404 не объявляются снятием. `removed` требует достоверной отметки именно известной исходной публикации; отсутствующий active-ID снятой страницы не становится обязательным условием. Неясное назначение редиректа даёт `unavailable`. |
| Сохранность приёма | Та же пара сохраняет прежние `ads` и `property_id`; старое время даёт `stale`, равное — `ignored`; более новое несовместимое `deal_type` — `conflict` после проверки времени. `unavailable` не изменяет данные и `observed_at`. Новых таблиц, полей или механизма алиасов не вводится. |

## Остаточные ограничения

- Сохранённые примеры подтверждают извлечение конкретных ID и различие известных форматов. Они не подтверждают вечную стабильность URL или отсутствие повторного использования ID самим источником. Проект прямо сохраняет эту границу; это не основание требовать новую схему хранения.
- Изменение query реально наблюдалось у Домклик24. Варианты с завершающим slash, регистром UUID, несовпадением ID и сменой семейства описаны как правила, а не результаты испытаний. При реализации потребуется проверить именно эти ветви и отсутствие записи при `unavailable`; сейчас отсутствие исполнения не снижает определённость спецификации.
- Сохранение принятых native-правил заявлено явно, но их фактическое исполнение и исчерпывающий перечень региональных hostname в данном ограниченном пакете не проверялись. Предложение не разрешает расширять этот перечень по суффиксу и не требует его пересмотра для новых семейств.

Реальной неоднозначности, при которой один и тот же поддержанный вход по тексту правила получает два допустимых ключа либо разрешает сохранить чужую карточку, в разрешённом пакете не обнаружено. Контрпримеры нестандартных URL в предложении не выдаются за наблюдения сайта.
